# 企业办公 Agent：工程归档与开发安装版

本仓库保留原 DSH Desktop 工程，并将企业办公 Agent 的 Harness 源码、原型、脚本、任务书和开发记录集中存放。原始工作目录与现有用户数据保留；迁移不覆盖正在运行的旧项目，也不把真实凭据打进安装包或推入 Git。

## 资料位置

| 目录 | 内容 |
| --- | --- |
| `development/deepseek-harness/` | 当前 Harness 源码及全部未提交的源码成果、任务书、架构文档、原始录制和测试输入；此处没有嵌套 `.git` |
| `development/企业工作台页面原型改造/` | HTML、JavaScript、CSS、Python/PyQt 原型与原型开发记录 |
| `development/企业工作台页面开发文档/` | 原工作区的架构分析、数据库设计等开发文档 |
| `project-docs/` | 迁移说明、公开交付状态和检查汇总 |
| `local-only/` | Git 历史包、原始补丁、会话记录、完整交接证据及私密归档；整个目录禁止提交 |
| `.build/` | 依赖布局、安装输入、实际检查日志等生成内容 |
| `dist-enterprise/` | 本次开发版安装产物，生成后在交付状态中记录摘要 |

初次迁入的19,362个文件共286,856,978字节，复制时逐文件核对SHA-256。三个来源仓库的Git历史保存为bundle，同时保留已暂存与未暂存补丁。`local-only`内的manifest记录文件摘要和历史状态；公开状态见`consolidation-status.json`。原型数据及含凭据风险的原始记录留在本地归档，不作为公开源码或安装输入。

工作区运行记录另按原相对路径保存24,944个文件，逐文件校验并记入私密manifest。三次tar归档的中断、保护性拒绝和失败结果均保留；逐文件保存不将失败压缩包标为完整。活动数据库和浏览器存储没有迁走，原目录继续保留。

## 默认 GUI 热开发

在仓库根双击`启动DeepSeekHarness.cmd`，或运行`npm run dev`，使用企业办公GUI热开发入口。`npm run dev:classic`保留原桌面工程的开发入口。Node运行时固定为24.22.0，当前Harness声明的pnpm固定为11.28.5，迁移时从已有且版本匹配的本地缓存准备，启动器不再依赖`D:\nodejs`。

开发窗口使用独立的`enterprise-office-agent-development`用户目录；测试或并行开发可以传Electron标准`--user-data-dir`参数选择另一目录。关闭窗口先等待本次服务停止，不按进程名称清理其他项目。登录凭据、当前会话及运行日志保存在用户目录，原项目的历史数据不会被替换。

仓库开发使用本目录的默认启动入口，并修改`development/deepseek-harness`源码。安装版监听其自带的运行快照，验证时不连接原仓库；需要提交源码的开发应使用仓库入口。

原控制器保留默认路径，并新增运行数据、Node目录与真实产物备份清单参数。首次启动在独立用户目录真实归档编译产物，再开启Client源码监听。TSX/CSS更新沿用已有Harness开发流程；服务端使用现有built CLI，修改Host源码后仍需相应编译和重启。

## EXE 开发安装版

打包入口为`npm run package:enterprise:win`。安装目标是Windows x64，采用单独应用标识，携带Electron43、Node24.22.0、匹配的pnpm和当前GUI开发运行输入。源码监听与严格类型诊断同时保留。新应用不使用旧0.2.0-rc.2桌面壳的后端冒充当前办公界面；原桌面源码及命令继续保留。

构建可设置`DSH_ENTERPRISE_FAST_BUILD=1`，临时解包和压缩改用系统TEMP目录，最终EXE和blockmap仍复制回本仓库`dist-enterprise`，已有版本不覆盖。修正版使用49152至65535范围分配本地端口，避免系统分配6000后被Chromium拒绝；原始失败版本及日志保留。

这是当前可运行GUI方式的开发安装输入，不是完整生产发布。既有built Host、当前源码和未通过的检查分开记录。当前整体仍为175项：137完成、35进行中、3未开始；186项Client诊断为主仓最近交接值，实际新运行结果另记。完整Host第三次构建失败以及旧Electron、终端、Steering等封顶记录不因目录迁移或新安装包重置；本次不运行第四次旧构建或改名重跑旧场景。

Electron安装载体和后台Node的版本不同：Electron43内置Node24.17.0，后台Harness和开发工具明确使用随包Node24.22.0。验证分别覆盖桌面原生目标、实际依赖布局和新安装流程；单项通过不代表175项或原六个Native父项全部验收通过。

## 构建与数据保存

开发安装流程消费保留的运行输入快照，不重新执行已经封顶的完整Host构建。忽略目录中的node_modules、lib/dist、工具链和安装包由准备脚本及本地运行输入产生，不能作为第二份维护源码提交。仅有Git源码的全新checkout不等于已拥有这份开发运行快照；完整可重复生产发布仍依赖后续被明确授权的构建和验收。

原运行目录、活动数据库、浏览器存储和用户配置没有搬走或重置。本地原始日志可能含认证信息，因此不能将`local-only`、运行数据目录或整个`.local-run`加入待推送文件。公开源码只包含经过检查的工程输入。安装程序不携带现有员工凭据或客户数据库。
