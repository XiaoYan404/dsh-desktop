# Agent Note: 在发布事项前预留内部 Agent 工作

Status: implemented

[English](2026-10-17-office-agent-work-reservations.md) | 中文

## 问题

已认证的 Agent 请求可能在创建办公任务后丢失响应。如果重试生成新的服务端事项编号，就会重复创建工作及负责人通知。准备好的关联快照也不能单独授权后续写入：员工、选择、必需连接及适配器可用性都可能在等待存储时改变。

## 决策

办公服务提供一个基于提醒模板捕获上下文创建内部任务／待办的封闭操作。认证员工来自服务适配层，不来自请求数据。共用队列检查成员启用状态、快照归属及角色、审核选择、当前声明依赖和必需连接版本。该操作不向外部公司系统发送请求。

发布普通工作提交前，独立预留领域先保存原员工、执行 UUID、严格请求指纹及服务端生成的事项 UUID。重试首先查找同一私有预留；若事项已存在，服务按当前读取权限返回它，不执行写入；若事项不存在，则重新检查当前执行权限，再创建同一预留编号。相同执行 UUID 改变请求会冲突。

事项、负责人通知及已有业务审计仍在一次工作领域提交中保存。单独的预留只证明请求已接纳，不证明执行成功。业务写入失败留下可恢复预留，提交后响应失败则可查回原事项。预留落库后、依赖连接的业务写入前，再次检查就绪状态及同步部署可用性，防止等待期间卸载适配器后仍按旧可用状态接纳工作。

预留具有有限的记录及字节上限，不隐式过期。降低上限后仍可准确重试已有记录，新请求达到容量时在创建新业务事项前失败。恢复会核对原员工数据及保存的指纹。普通人工创建工作共用事项发布函数，保留原 API。

## 考虑过的替代方案

**只在创建任务后保存回执。** 任务与回执发布之间崩溃或响应不明，会留下无法可靠重试的区间。

**使用特定后端事务一次提交预留及工作。** 办公组合支持独立存储领域及 JSON 提供方，要求多领域事务会让该操作依赖新的后端约定。

**信任捕获角色或初次就绪检查。** 它们属于历史事实。待处理预留可能跨越适配器卸载或部署依赖变更，因此需要当前接纳检查。

**返回已提交重试前再次检查写权限。** 这会在取消关联后隐藏已成功的操作。返回有权查看的原事项属于确认恢复，不是再次执行。

## 验证

真实 Loader／JSON 测试覆盖并发重试、冷恢复、预留前故障、业务发布前故障、持久发布后故障、额度拒绝、排队停用、角色变更及关闭排空。适配器卸载用例在第二次接纳检查加入前失败，加入后通过。实际 HTTP 及独立认证员工 Host 验证私有快照归属、伪造操作者拒绝、仅一次事项／通知，以及替换 Host 后回执恢复。

## 后果

两次有序持久写入替代跨领域事务。未完成请求会占用保留容量，直至显式管理；备份需同时包含预留、快照及办公工作。已提交的重试反映事项当前可读状态。这项保证属于单个服务办公队列及其存储所有者。原生模型工具暴露及外部系统写入属于单独消费方，具有各自的审批和执行约定。
