# Agent Note: 在明确原生提交时捕获 Host 上下文

Status: implemented

[English](2026-10-17-prepared-native-prompt-context.md) | 中文

## 问题

已提交的原生提示词在收件箱等待时，办公关联仍可能改变。若到模型派发时才读取当前关联，描述的员工选择就可能与提交时不同。在浏览器准备上下文会让元数据接纳受到客户端竞争影响，并需要第二套提示词表示。独立原生注入也可能赶不上已经开始确定的步骤。

## 决策

Session Controller 在收件箱接纳前等待 Host 拥有的准备 waterfall。其载荷包含已解析的 Session 编号、原生请求编号、投递模式及控制器生命周期。提供方返回不可变文字和非人类来源元数据。原用户消息通过 RPC 来源上的可选 `preparedContexts` 保留这些贡献；普通输入省略该字段。并发重试共用一次准备，提供方失败或卸载会阻止接纳。

控制器在进入步骤的 pre-step 中，将每项捕获贡献物化为原输入前独立、带标识的上下文消息。原生技能注入保留现有顺序及加载器。Agent 投递 API、单条消息唤醒约定及模型 surface 推导均保持不变。队列文字编辑保留捕获来源，后续关联修改不会改写它。pre-step 拒绝时，继续遵循已领取输入不重新排队的原生规则。

这是[上下文独立交付](2026-07-24-separate-context-injection-from-turn-execution.zh.md)的一项 Host RPC 专用例外：准备元数据随排队输入保存。它没有恢复 `SendOptions.contexts`、prompt-prefix 放置或调用方提供的封套。核心收件箱代码只携带普通冻结消息，不解释这一字段。

办公准备使用已认证的集中快照服务。快照描述所选系统、就绪状态及未满足的依赖，不含连接地址或凭据，也不授予执行权限。从未保存的选择不提供贡献，审核后的空选择提供明确的空快照。确认退出办公登录后，受信任 Host 保留原有原生能力。运行故障仍按失败处理。原生聊天继续隐藏普通上下文，轨迹展示已记录的输入及提供方元数据。

## 考虑过的替代方案

**只在 pre-step 读取关联。** 排队提示词会采用后续编辑，丢失明确提交时的选择。

**先独立注入上下文，再唤醒输入。** 注入按最近边界交付，可能进入另一条运行中的请求；其交付和取消也与准备中的提示词分离。

**把上下文拼入用户文字。** 这会改变界面所呈现的用户原文，并在原生输入、历史和模型请求中重复处理封装。

**恢复通用 Agent 上下文附件。** 这会把 Host 专用事务扩散到所有 Agent 调用方。RPC 来源元数据将该策略留给负责接纳的所有者。

## 验证

原生命令及真实认证办公 Host 测试覆盖并发重试、提供方失败、卸载、空选择、不透明请求编号和跨账号快照拒绝。浏览器验收检查实际用户消息只有一条、关联并发修改后的冻结选择、模型输入文字、原生技能指令、附件字节及轨迹刷新恢复。原提交基线及当前 JSONL 后端均能读取同一份实际提交日志，不改变其字节，也不丢弃办公元数据。

## 后果

准备文字先保存在排队来源元数据中，随后保存为独立上下文记录。这增加存储及请求 token，但保留提交证据且不改写旧历史。集中准备可能在后续原生接纳失败前已经提交，因此它只是证据，不是送达证明。审核选择改变后，先前未接纳的重试可能被拒绝。旧 Host 可保留并推导已记录上下文，但未实现对新来源元数据中待处理准备的物化；办公业务执行仍需要自己的当前授权。
