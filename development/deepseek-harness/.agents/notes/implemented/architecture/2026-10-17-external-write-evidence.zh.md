# Agent Note：外部写入证据将派发与已知结果分开

Status: implemented

[English](2026-10-17-external-write-evidence.md) | 中文

## 问题

外部系统与办公 JSON 后端不能提交同一个共享事务。派发后超时或确认丢失，不代表客户操作失败。把它当作普通重试会重复业务副作用，而在收到并保留权威证据前存储成功，则可能虚构结果。

## 决策

独立版本化执行领域预留按员工隔离的请求及独立服务端执行标识。受信任办公队列先记录派发，独立执行器之后才可发送。已派发证据投影为未知结果，不能再次派发。明确的未知证据只能归结为权威成功或拒绝，取消仅适用于尚未派发的预留。准确的终态确认保留原版本。

接纳时预留最大审计信封及请求确定的结果容量。未结束请求保留该容量，终态才释放未使用空间，防止外部副作用发生后出现可预见的容量失败。结果上限属于已接纳请求，降低部署默认值不会静默改变原契约。持久失败保留先前保守阶段，不报告成功。

私有回执投影不含输入值及重试指纹，读取由当前员工认证控制，管理员没有归属绕过权限。证据损坏或原目录／系统目录丢失时拒绝启动。重启不会将保留的派发解读为重放许可。账本持有证据；独立的队列内写入协调器在接纳前强制声明角色、准确适配器／连接版本、平面文本字段及可选私有捕获。新的重试 UUID 也不能重放相同的未决业务操作。

可选受信任适配器获得即时私有凭据、已认证员工身份，以及用作外部幂等键的服务端执行标识。协调器先持久派发，再调用适配器。派发后的协作中止、无效结果和意外缺陷保留未知证据；稳定处理错误只在私有 cause 中保留诊断。权威结果必须提交后才能返回成功。封闭办公请求清单暴露此协调器，不暴露原始账本变更或任意传输。

## 考虑过的替代方案

**重试每个失败请求。** 传输失败可能发生在远程操作已经提交之后。账本要求权威核查，而不是假定操作不存在。

**外部调用之后记录派发。** 副作用与本地标记之间崩溃，会留下看似可安全重发的预留。持久标记先于副作用。

**只计当前 JSON 字节。** 已接纳的远程操作可能在结果到达时用尽剩余额度。派发前预留结果和审计容量，限制后续增长。

## 验证

真实 Loader／JSON 测试在重启后保留标识，将已派发记录投影为未知，并拒绝重复派发。故障注入覆盖预留、派发及终态提交。其他用例覆盖私有归属、改变的重试、键序稳定性、取消限制、单调时间、多字节上限、结果容量预留、策略变化、损坏及目录丢失拒绝加载。真实本地 HTTP POST 验证派发持久性、凭据轮换、服务端员工身份及幂等键。已提交但未确认的响应、超时、适配器替换／卸载、根关闭排空和会话过期均不授予重放许可，也不向过期身份披露延迟私有结果。

## 影响

内部办公创建保留原预留所有者和事务语义。外部写入证据不改变 Session 格式、原有原生工具或原办公领域。可选的作用域原生消费方提供业务写审批，将真实回执追加到模型历史。员工工作台读取有上限的元数据页及明确回执详情，不重放操作；游标及详情标识仍由当前员工私有持有。声明员工表单在发送前审核准确字段，模糊响应后保留同一内容／重试 UUID。这些表单操作不添加原生模型消息。明确的只读核查器可按当前权限及原结果上限更新原回执，提供方缺失及不确定性不会授予再次派发权限。仅预留意图不会授予执行许可，未知结果需要权威核查，不能自动重发。
