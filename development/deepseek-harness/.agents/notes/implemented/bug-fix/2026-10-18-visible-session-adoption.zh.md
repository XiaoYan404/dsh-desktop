# Agent Note: Check current visibility at explicit Session adoption

Status: implemented

[English](2026-10-18-visible-session-adoption.md) | 中文

## 问题

显式 ID 的创建请求可以复用活动 Agent 或恢复持久历史。枚举、改名及提示词入口的权限检查不能约束这条接管路径。更换员工后可能激活私有历史，cwd／预设冲突也可能在核验前泄漏详情；共用创建及竞争中的活动对象回退还可能晚于先前的策略结果。

## 决策

[Host Agent 控制器](../../../../packages/api/session-controller/src/agent.ts) 在接管边界调用既有可见性 waterfall：检查已知活动／冷标识后才核对私有兼容信息，组合后、冷激活前再次检查，并在返回 Agent 前核验等待同一创建 Promise 的每个调用方。可见性拒绝在竞争活动对象回退前传播；其他创建失败仅可在再次检查可见性后复用竞争中出现的活动 Agent。命令在挂接工作区前及异步结束后核查当前可见性。

[Client 引用决策](../architecture/2026-09-15-client-session-references.zh.md) 继续拥有借用绑定及被持有的 Client 代次；[空白会话策略](../architecture/2026-09-17-process-local-blank-sessions.zh.md) 继续选择并复用空白。Host 独立核对所选目标的当前可见性，不改变这些 Client 生命周期规则。

同一控制器在交付作用域活动对象或激活已持有的观察前、异步组合后，以及每个共用恢复的等待者处检查当前可见性。[上传服务](../../../../packages/client/file-upload/README.zh.md) 将登记的解析器作为活动和冷目标的授权来源，在存储字节前及发布凭证前分别核验，并检查准确 Agent 身份和解析器贡献。解析器卸载后拒绝上传，直到替换项登记；始终未登记解析器的 Host 保留独立原生行为。插件卸载会中止流式存储；已保存但未发布的内容寻址对象仍保留，因为删除它可能移除共享字节。

工作区元数据沿用同一历史授权。仅在 Session 控制器检查，无法保护归档触发的取消、全局置顶和排序锚点。因此注册表在自身执行端为元数据变更准入，并在异步预检后再次检查；API 在交付响应和流时筛选标识，不删除持久成员。已准入的持久写入可能在退出后完成；已授权的归档停止请求仍属于同一次操作。这项策略不会将共享 Host 目录转为员工所有的文件系统。

文件预览独立于 Agent 查找来解析 header，因此其所属文件服务在查找或文件系统访问前检查 Session，并在交付字节、元数据、含路径的错误或监听帧前复核。策略返回登记生命周期并保留已委托的生命周期；撤回会抑制待交付读取并关闭已持有的监听。策略一旦参与，空链就持续不可用直到替换项登记，沿用上传解析器的既有撤回规则。始终没有安装策略的原生 Host 保留其组合文件系统权限。

[终端控制器](../../../../packages/api/terminal-controller/README.zh.md)还拥有绕过新 Agent 查找的元数据及持续流。它按 Session 标识检查列表与窗口持有，不激活 Agent，并按当前授权检查每条快照、输出及状态帧。策略生命周期在撤回时关闭已持有的跟随者或窗口持有；空链不能恢复不受限访问。拒绝只关闭观察，不关闭 shell，保留终端所有者独立的进程生命周期。Host 列表消费方等待授权并传入请求取消；生成的 Client 协议不变。

## 考虑过的替代方案

**仅在创建包装层检查。** 包装层无法在内部异步接管的准确激活点执行准入，也无法在私有 cwd／预设错误前拦截。

**仅在接管后检查。** 请求可能已经激活他人历史并追加原生生命周期元数据。提前检查阻止这些效果，后续检查覆盖权限变化和等待共用创建的调用方。

## 后果

安装策略的部署会为接管和作用域解析增加异步检查；无提供方的原生部署继续保留普通创建、写锁及幂等行为。已有 Session 记录和传输类型不变。定向测试覆盖隐藏的活动／冷办公历史、审核或存储期间更换员工、原员工恢复、原生重复接管及上传解析器卸载；其他操作继续由原策略所有者负责。
