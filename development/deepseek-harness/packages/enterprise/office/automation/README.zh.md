# 办公自动化参考

[English](README.md) | 中文

## 概述

可选的 Office 自动化规则将稳定的表单、可信业务事件、已认证 Webhook 及原生定时任务发生记录，保存为员工私有待审核记录。它复用既有连接器动作目录、当前员工／角色检查、原生审批和执行账本，不拥有调度器、任意 HTTP 写入器或推断的模型完成信号。省略 `automations` 时不启用领域和产品入口；配置时必须显式提供 `maxRules`、`maxRuns`、`maxBytes`。

<a id="rules-and-approval"></a>
## 规则与审核

私有规则包含准确声明的写动作、当前连接／提供方版本、原样业务文本、触发类别／来源及可选的显式补偿动作。创建、编辑、启用、禁用均使用展示的规则版本。所有者与准入角色由当前认证成员决定。不支持载荷插值或调用者指定员工、传输、凭据。启用检查当前声明字段；提供方消失后仍可禁用。编辑使旧版本待运行失效。

触发只创建 `pending_approval` 运行。公共 `automation` 请求仅接受闭合的 `list`、`save`、`form`、`review`、`execute`、`manage`、`recover` 命令，不公开业务事件、Webhook 或定时触发路由。`review` 返回准确运行版本、动作、原样字段和原请求 UUID。显式页面确认或原生写审批后才调用 `executeReviewed`。原生执行还绑定当前提交选择的系统捕获，并逐一比较保留运行的字段及版本。原生审批默认仍为手动；工具的独立启用必须配合权限端配置。

<a id="trigger-sources"></a>
## 触发来源

仅可信 Host 的 `admitAutomationTrigger` 使用部署固定员工和配置来源。按规则身份及原发生标识持久防重放，跨规则编辑保留；修改载荷或规则版本不会制造新发生记录。不自动进行外部写入。

本项目 Webhook 辅助函数对原始字节验证 HMAC-SHA256 小写十六进制签名，签名输入为 `timestamp + "." + body`。时间戳是配置 `maxSkewMs` 范围内的规范纪元毫秒文本；每次新解析的密钥至少 32 字节。正文准确为 `{"protocol":1,"eventId":"UUID"}`；员工与来源取自私有端点绑定，不从正文读取。调用前限制原始请求缓冲，部署 HTTPS／网络规则并从已有 Host 凭据解析密钥。持久发生记录负责重放防护；本地准入不证明远端送达或业务完成。这不是企业微信或 OA 厂商的回调签名协议。

原生定时辅助函数仅消费已配置员工、原 Session、Schedule 标识下真实持久化的 `lastDelivery` 回执，准入前检查当前 Session 归属。没有投递证据则不创建运行；收件箱回执不证明模型执行完成。[来源适配器](../src/automation-native.ts) 通过提供的原 `schedule/changed` 订阅和当前授权目录读取器消费记录，注销时中止并排空读取；部署后可显式刷新。不合成遗漏或裁剪记录，不新建计时器、不修改原任务。原生工作流及日常办公技能保持原执行归属。

<a id="recovery-and-compensation"></a>
## 恢复与补偿

运行保留主操作／补偿的请求 UUID 及原连接器账本引用。只有其权威回执才能确认 `succeeded` 或明确 `rejected`。派发中或回执／存储失败均保守显示未知。恢复按保留执行标识查原账本，未取得执行标识时才按原请求 UUID 查找；只调用现有原执行核查。原账本没有回执时仍未知，不重发。等价未决写入可以复用同一账本执行标识，同时保留各自自动化请求身份。

明确成功后可申请已配置补偿，补偿有独立待审核状态和 UUID。未知主操作不能补偿或重试。明确未受理或派发前取消后，才可显式创建需要重新审核的子重试。补偿失败的重试保留已确认的原主操作，使用新的补偿请求，绝不重放主操作。原运行与回执持续保留。补偿是另一次授权的业务操作，不宣称事务回滚。

<a id="storage-and-lifecycle"></a>
## 存储与生命周期

`enterprise_office_automations` 版本 1 是新领域；旧 Office、发件箱、执行账本、Session 代际保持原样。严格持久读取拒绝归属矛盾、重复发生及请求重绑定。容量上限停止新准入，不删除防重放或恢复证据。规则／运行先提交再发布，调用外部执行所有者前先保留运行标记；结果存储失败保守保留前态。若在运行标记与连接器预留之间崩溃，可能没有原账本回执；只能保留未知并取得权威调查结果，不能盲目重试。

修改使用单一串行所有者；关闭时停止准入并排空已接受工作，再关闭领域。恢复必须保留原员工目录；备份同时包含此领域、身份／目录、集成、连接、执行账本及提供方发件箱。提交后的 `office/automation-audit` 只包含规则、运行、版本、阶段、执行、系统、动作标识和状态，不包含字段、凭据、远端正文或地址。审计观察者失败不能撤销已提交修改或授权重试；保留状态仍是恢复依据。

<a id="product-integration"></a>
## 产品接线

Client 叶子提供账号／角色／对话框迟到响应隔离、仅选择声明动作的严格规则编辑器、私有运行列表、保守的未知结果控件和独立准确补偿审核。本地化错误指引用户先刷新原状态；渲染不派发，来源配置与规则保存明确分开。Host、Remote、Client slot／Locale 及原生工具注册由公共整合补丁接入；源码／组件验证不等同正式页面或发布构建验收。

GUI 仅在当前自动化列表成功读取后开放修改。服务不可用时保留缓存记录，不把空列表当作读取成功。编辑器在请求期间锁定输入，切换系统目录失败时保留未保存文本，操作不再可用时要求明确选择替代项。另一系统的补偿以只读方式保留原字段和原坐标，直到用户明确移除；当前系统的补偿要求版本有效。同一表单来源会为所有匹配的已启用规则创建运行，每项操作仍需单独审核。

运行列表支持按规则名称、来源、来源事件及原请求／执行标识检索。详情同时保留主操作和补偿结果，并解释规则修改或禁用后的执行限制。审核展示目标系统、原请求、运行版本、连接／提供方版本及原样字段。修改回执丢失后，必须成功读取当前记录才能继续修改；恢复仍只核查原执行。新规则创建回执丢失时，刷新后也不会重新提交该草稿，因为保存接口没有客户端拥有的创建回执。编辑器内可直接刷新，无需再次保存。

<a id="known-limitations"></a>
## 已知限制

真实客户凭据和来源绑定依赖部署。原生 Schedule 订阅、业务事件生产者及 HTTP 入口需真实授权的 Host 接线；辅助函数验证不证明来源已连接。自动审批状态订阅需要单独授权的读取同步策略。规则保存丢失响应后不自动重试修改，需先刷新当前配置。没有原权威证据的未知写入可能需要客户调查。不宣称第三方副作用恰好一次。
