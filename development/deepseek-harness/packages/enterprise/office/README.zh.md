# @deepseek-ai/dsh-enterprise-office

[English](README.md) | 中文

## 概述

创建员工任务、待办和单日日程，邀请同事并在重启后保留回复。负责人和受邀人收到持久化的收件箱记录。有权员工可修改事项状态和个人联系资料，管理员可管理成员并查看审计记录。本包需要受信任的员工认证适配层，不负责浏览器认证，也不替换 Agent 会话、执行权限或定时提示。

网盘可选图片、授权知识库和办公交付检查的配置、权限、保留及限制见[网盘读取参考](drive-readers/README.zh.md)。

## 使用本包

管理员可通过 `memberInvites: { maxTtlMs: 3600000, maxEntries: 1000, maxBytes: 1048576 }`，为已存在且启用的成员开启首次密码邀请。三个正安全整数上限均必填；省略配置时功能关闭，也不打开新领域。管理员核对成员当前角色和到期时间后，`issueMemberInvite` 仅首次返回邀请码，由管理员复制后自行私下交付。相同签发 `requestId` 的精确重试只返回元数据；丢失邀请码须明确重新签发，同一次提交会撤销上一个邀请码。服务不发送邮件或外部消息。

接收人在员工 Host 提交邀请码及 15–1024 字符的首次密码。`acceptMemberInvite` 从邀请码确定目标，哈希后重新检查期限、撤销状态、签发人的当前权限和目标的启用状态及角色，只向原 identity v1 领域提交目标的首份凭据。一旦成员已有凭据，其全部邀请码均不可用，重启后也相同；邀请接受不能重设密码。身份审计沿用 `credential_set` 动作，操作者为目标本人。成功只返回 `memberId`，不创建会话，仍须单独正常登录。管理员 `memberInvite` 视图分别呈现当前凭据、到期、撤销及待复核事实，不暴露秘密，也不声称具体邀请码的接受时间；`revokeMemberInvite` 不删除已设置密码。

停止服务后，将 `enterprise_office_member_invites`、原员工通讯录和 `enterprise_office_identity` 作为一致快照共同备份。独立 v1 邀请账本仅保存签发／撤销元数据、请求指纹及邀请码 SHA-256 哈希，不存原始邀请码或密码。接受邀请只提交一次身份数据，不增加第二份“已消费”标记。因此恢复较旧凭据快照可能使保留的邀请码再次可用；非一致恢复须在重新开放服务前撤销未结束邀请码。全部保留行计入显式条目上限和完整紧凑 UTF-8 global JSON 字节上限，不自动清理。容量耗尽保留已有数据和重试回执；降低配置至小于已有体积可能使后续修改被拒绝。原 Office、身份及 Native schema 保持不变。

私有定制需求持久保存系统或技能名称、联系人及说明，不提供外部发送通道。`customizationMaxOperations` 默认保留 1,000 条不可变保存回执，`customizationMaxBytes` 默认限制完整 UTF-8 领域 JSON 为 16 MiB；达到任一上限拒绝新保存并保留原请求重试回执。备份包含 `enterprise_office_customizations` 及原员工通讯录。元数据分页不含联系人和说明正文；详情和编辑仅限所有者，管理员同样不能绕过。[员工页面](../../client/ui-office/README.zh.md#use-this-package)负责审核导出及冲突恢复。

工作发起人和管理员可通过 `changeWorkLifecycle`，按已查看修订号填写说明并确认归档、移入回收站及恢复。仅成为负责人不授予此权限。`view.items` 及日常统计只包含活跃工作；`view.inactiveWork` 仅返回有权查看的归档／回收站记录。非活跃事项拒绝活跃读取及修改，但附件仍按当前网盘权限授权下载。恢复保留编号、状态、分派、期限、子项、文件和业务历史，交付须重新提交。变更原子保留生命周期历史、带事项标题的收件人通知及审计。网盘文件和原生会话保留。共享部署前参照[生命周期升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-work-lifecycle/guide.zh.md)。

工作附件关联最多 20 个不同网盘文件的已确认版本。发起人、当前负责人或管理员按已查看的事项修订号替换关联；保持原引用不要求新增网盘授权。新增或变更引用须有当前文件权限且版本一致。关联不复制文件，也不改变网盘权限。`workAttachments` 对无权或版本变化的引用隐藏文件名和元数据；`workAttachmentInfo` 在下载前检查事项和文件的当前权限及真实字节。移除关联保留源文件。修改原子提交 `work_attachments_updated` 通知和审计，并使待验收交付失效。提交和确认交付须能访问所有已确认的当前版本，退回仍可操作。共享数据编辑前参照[附件升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-work-attachments/guide.zh.md)。

初始配置仅用于尚未初始化的领域。修改配置后重启不会覆盖现有企业数据或成员。后续成员变更通过 `saveMember` 检查活动管理员权限。适配层必须先认证员工再传入操作者 ID；直接接受浏览器自报的员工 ID 不安全。

创建成员时将 `saveMember` 的第三个参数设为 `null`；编号已存在时返回 `conflict`，停用成员也不能被重复创建。编辑时传入此前查看的完整成员记录。服务在提交队列内比较字段，拒绝过期编辑，不改变业务数据及其审计。省略此参数保留受信任适配器的更新或创建行为。最后一名启用的管理员不能被移除或降级。仅管理员视图包含 `managedMembers`，其中保留停用身份；普通 `members` 通讯录只包含启用成员。

恢复启用先移除该员工保留的登录会话。持久 `session_revoked` 记录以发起恢复的管理员为操作者、该员工为目标。身份和成员使用独立提交：后续成员保存失败时，员工保持停用，已完成的会话回收记录继续保留。

启用的管理员通过已认证办公请求 API 调用 `auditPage` 或 `auditExport`。两者均须显式提供 1–100 的 `limit`，首批传入 `before: null`，后续使用返回的 `next` 读取更早记录。可选精确筛选为 `source`、`actorId`、`targetId`、`action` 及包含端点的 Unix 毫秒时间 `since`／`until`。来源包含业务变更、身份、组织、网盘、集成导入、连接保存及 `request_denial`。记录仅返回来源、修订号、操作者、操作、目标和时间；请求拒绝另返回安全的 `denialCode`。`auditExport` 返回 NDJSON 内容及条数、总数和续读位置，不包含凭据字段、业务正文或连接配置。每页及每批导出重新检查当前管理员权限。同一时间按来源升序、修订号倒序稳定排序；分页读取当前保留历史，不是冻结快照。

通过解析和认证的 `saveMember`、`setStatus`、`reply` 及 `saveDrivePermissions` 请求，将队列内业务拒绝保留到独立的 `enterprise_office_request_denials` 第 1 版领域。每条记录仅含递增修订号、认证员工、服务端选定操作、已校验目标 ID、时间及 `forbidden`、`not_found`、`conflict`、`invalid_input` 或 `unauthenticated` 安全错误码。排队期间会话被撤销时，保留最初认证的发起人；初始身份缺失或无效时不猜测员工。格式错误请求、其他方法及基础设施故障不在此台账范围内。不保留请求正文、凭据或错误文本。

拒绝审计写入仍在既有修改队列内，完成后才返回原业务拒绝；被拒绝业务不变，不发布业务成功。关闭时排空已受理写入。条数或字节容量达到上限时保留全部旧记录，拒绝新增拒绝记录。拒绝审计写入失败时返回安全的 HTTP `503 unavailable` 并输出固定服务端警告；业务继续拒绝，其审计尚未确认。重试前恢复存储或提高配置容量。备份须同时包含此领域与原员工目录；操作者缺失或历史无效时拒绝启动。六类来源的管理员检索和 NDJSON 导出尚未包含此独立台账。

员工可读取自己发起、负责或参与的事项，管理员可读取全部事项。隐藏和不存在的事项均返回 `not_found`。只有主办人或管理员可修改整场日程的状态，受邀人只能回复自己的邀请。停用成员不能继续读取或修改数据，排队操作也在执行时核查停用状态。编辑联系资料不能改变授权角色。

时间判断统一使用同一次服务器观测及已保存的公司时区。任务或待办填写了具体时间时，以该本地时刻为截止瞬间；未填写时，以次日本地零点为截止。按日历推算次日，保留 23 或 25 小时的日期。重复的本地时刻选择较早的 offset；不存在的本地瞬间须核对。日期保留既有 0000–9999 年范围，9999-12-31 的无时间事项须填写具体时间，不能让次日截止越界。已完成、已取消、已归档和已删除事项不标为未完成逾期。会议的未开始、进行中和已结束阶段与已保存状态分别投影。

时间判断仅返回当前员工有权读取的事项，包括原本可读的保留非活动事项。已知的存档时间问题只令该项显示待核对，其他事项继续可用；未知或基础设施故障仍拒绝读取。读取不修改事项状态、不持久化时间判断，也不调度提醒。投影字段可选，旧服务器继续保留原有工作台界面。

中央提醒须在权威 Office 服务显式配置 `reminders`。省略时不打开提醒领域、不启动提醒定时器，也不返回 `view.reminders`。一个有归属的轮询在前次扫描结束后才安排下一次，扫描与业务修改共用队列。事项到期提醒仅投递给当前启用负责人。会议开始提醒投递给启用的组织者及当前待回复或已接受的邀请人；已拒绝、已移除或停用成员及已结束会议不投递。超过补发窗口、已关闭或非活动事项以及公司时间待核对的记录不投递。本服务不创建原生定时提示或外部消息。

独立的 `enterprise_office_reminders` 第 1 版账本按事项、提醒种类、发生时刻及收件人在重启后去重。内容编辑、进度变化和邀请回复不会令同一发生记录再次提醒。截止时间或收件人变化在下次扫描重新判断；旧记录不再投递给原负责人。收件视图只返回当前仍符合资格且有权读取的事项，标题从当前事项派生；完成、取消、归档、删除、改期或收件资格丢失后隐藏失效提醒。会议结束后隐藏该会议提醒。`markReminderRead` 只确认当前收件人仍可见的 UUID；重复确认已读不写入，隐藏及他人记录统一返回 `not_found`，管理员同样不能绕过。

一次完整扫描批次提交前，按全部保留账本检查条数及字节上限。容量策略不裁剪已读或已失效的去重标识。容量或存储失败不发布部分投递；固定警告说明受影响的提醒操作及存储或容量恢复方式。后续轮询可在补发窗口内安全重试未提交记录。观察者失败不能撤销已提交批次。停用配置或卸载会阻止新轮询，排空已受理写入后再关闭领域；在途提交的记录继续保留，关闭期间不再发布迟到通知。重新启用后恢复去重及已读状态。备份包含该领域及原员工和事项目录；无效、脱离原目录或超出容量的历史会拒绝启动。

主办人和管理员可携带已查看的修订号，编辑未关闭会议的标题、日期、时间、地点、备注和受邀成员。会议标识和主办人不变，主办人始终参与。省略 `inviteeIds` 保留成员，空数组移除其他参与人。新增成员必须处于启用状态，并收到邀请。被移除的普通成员失去日程读取权限，移除通知保留此前标题；同次编辑修改标题时也不会泄露新标题。仅改成员时保留原答复，修改日期或时间则要求受邀人重新答复。事项、通知和审计一并提交。已关闭、无权或过期修改均不发布变更，内容和成员均未变化时不写入。新增审计和通知类型要求按[成员升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-schedule-members/guide.zh.md)协调部署。

负责人可接受待处理任务使其进入进行中，或说明原因拒绝任务。负责人、发起人或管理员可说明原因，将未关闭任务转交给其他启用成员，任务重新进入待处理。每次操作在写入队列内核对已查看的事项修订号和当前权限，并随任务保留操作、操作者、时间、原因及前后负责人。事项、接收人通知和审计一并提交。转交后原负责人失去任务读取权限，但通知仍保留标题快照。普通状态编辑继续可用并保留操作历史；待办拒绝 accept/reject 操作，日程使用独立控制。与旧办公读取器配合使用前，按[任务升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-task-decisions/guide.zh.md)操作。

同一个 transfer 操作可将未关闭待办转交给其他启用成员，使其重新待处理。负责人、发起人或管理员须使用已查看的修订号并填写原因。待办标识、内容和截止信息保留，独立的待办转交历史在后续内容或状态修改后继续保留。事项、`todo_reassigned` 通知和审计一并提交。原负责人失去读取权限，通知仍保留标题。[待办升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-todo-assignment/guide.zh.md)规定协调部署及旧读取器明确拒绝的行为。

发起人、负责人和管理员可携带已查看的修订号，编辑未关闭任务或待办的标题、说明、本地日期和可选截止时间。不提供时间会清除截止日期中的具体时刻。标识、种类、状态、负责人和操作历史保持不变。相同输入不写入；内容变化将事项、`work_updated` 通知和审计一并提交。会议使用独立编辑器。[事项编辑升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-work-edits/guide.zh.md)规定存储这些新通知和审计类型前的协调部署要求。

`OfficeWorkPriority` 支持低、普通、高和紧急。既有及新建事项默认普通，新建接口和原生工具参数保持原合同。`updateWork` 接受可选优先级：省略时保留已有值，明确指定普通时移除非默认值。优先级发生实际变化时，事项、`work_prioritized` 通知和审计一并提交；相同优先级不写入。优先级不改变日期时间排序和转交历史。存储这些新增判别值前须按[优先级升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-work-priority/guide.zh.md)部署。

人与人私聊使用独立的 `enterprise_office_chat` 领域。`chat` 仅返回操作者本人的会话，管理员也遵守此限制；通过排他的序号游标每次读取最多 100 条消息。`sendMessage` 要求客户端提供 UUID，相同发送人、接收人和文本重试会返回已提交消息，不重复发送。`readChat` 只接受属于该参与人组合的游标。消息保留历史姓名，成员停用后，另一位启用成员仍可读取自己的聊天历史，但不能继续向其发送消息。聊天写入与成员变更共用队列，持久化成功后才发布事件，卸载前等待已受理写入完成。存在历史消息而办公通讯录丢失时拒绝启动，不会重新初始化其他公司覆盖这些消息。

未发送草稿使用独立的 `enterprise_office_chat_drafts` 第 1 版领域。`chatDrafts` 只返回认证员工本人的文本和联系人版本，管理员也不能越过此范围。`saveChatDraft` 接收已查看版本及 UUID 重试标识；原样重试返回已提交版本，过期窗口得到 `conflict`。空草稿保留版本墓碑，防止旧窗口恢复已清除文本。变更事件不携带正文，私有视图重新检查启用成员资格。既有工作和聊天领域的数据结构保持原样。

修改在存储提交和版本通知派发后完成。校验失败、事项版本过期或权限拒绝不改变业务数据。后端写入错误原样上抛，不发布成功。通知观察者失败会记录日志，不会把已提交的操作报告为失败，也不会阻止其他观察者运行。关闭时立即拒绝新操作，等待已接收的修改完成，再关闭所有办公领域。

受信任的服务端适配器可为已有管理员一次性初始化密码登录、开通员工账号、签发持久会话、撤销本人会话及修改密码。密码要求 15–1024 个字符，使用独立随机盐和 scrypt（`N=131072, r=8, p=1`），依据 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)和 [Node crypto 契约](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)。独立的 `enterprise_office_identity` 领域仅保存令牌哈希。会话八小时后过期，每位员工最多五个；重置或修改密码会撤销全部旧会话。每次认证重新读取成员启用状态和角色，重新启用成员前清除停用前的令牌。登录初始化后，必须保留至少一名有凭据的启用管理员。后续启动参数不会重置已有密码。独立的[办公网关](../office-gateway/README.zh.md)提供 HTTP 认证和明确的办公操作白名单。会话绑定请求在排队写入执行时再次校验，已撤销令牌不能授权后续写入。原生 Agent 能力保留在员工自己的 Host 中。

内部会议忙闲共享需在办公服务显式设置 `scheduleAvailabilityEnabled: true`，默认关闭。启用员工可查询最多 500 名启用同事在一个办公本地日期及时间区间内的忙闲。只读结果返回去重成员编号、布尔占用、办公时区和查询时间，不包含会议编号或内容。未关闭会议中待回复或已接受的参与占用时间；已拒绝、已完成、已取消及首尾相接的会议不占用。排除会议须先拥有当前读取权限。任务及外部日历不在范围内，查询不会预留时间或限制其他合法保存。本地工作台补丁明确开启共享；网关部署须在中央办公服务配置此策略。

任务和待办可保留最多 100 个清单子项。发起人、当前负责人或管理员按已查看的父事项修订号替换清单；输入中的空编号由服务端生成身份，保留编号必须属于当前事项。子项继承父事项权限，不作为独立委派。勾选子项不改变父事项状态、优先级、截止时间或任务操作历史。相同清单不写入；关闭、无权或过期修改不发布。清单、`work_subtasks_updated` 通知和审计一并提交。修改共享数据前参照[子任务兼容指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-work-subtasks/guide.zh.md)。

任务交付通过明确操作执行：负责人提交进行中的任务，发起人或管理员确认或退回。每次操作保留非空说明、操作者、当时负责人、时间及事项修订号。待验收提交必须仍对应当前事项修订号和负责人；内容、子项、转交或状态变化后须重新提交。确认后任务完成，退回后继续进行中。首次提交后，普通状态修改不能完成该任务；没有交付历史的旧任务保留原状态操作。历史、通知和审计一并提交，共享部署前参照[交付升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-task-delivery/guide.zh.md)。待办和会议不使用任务交付验收。

## 理解实现

公司公告使用 `enterprise_office_announcements` 第 1 版领域。仅启用的管理员可以发布纯文本公告或撤回已核对的发布记录；一次提交保存不可变正文及发布时的在职接收成员快照。全体公告不会自动投递给之后入职的成员，指定接收人必须处于启用状态。相同 UUID 重试返回原发布记录，复用 UUID 却改变内容会被拒绝。接收人只确认本人仍有效的投递，重复已读不再次写入。撤回后接收人不再看到该公告，作者、正文、撤回操作者/时间及已读记录仍保留。管理员可管理保留记录；普通视图不包含其他接收人和已读记录。既有工作、聊天、身份与会话结构不变。变更事件不携带正文，客户端重新读取授权视图；存储失败不发布成功，观察者失败不能撤销已提交操作。

公司集成登记使用 `enterprise_office_integrations` 第 1 版领域。启用成员在办公视图中读取描述性清单，只有当前管理员可调用 `importIntegration`。严格 JSON 对象必填 `name`、`system`、`version`、`provider`、`description` 及 1–30 个不重名的 `capabilities`，`owner` 可选。导入按完整 UTF-8 字节检查 256 KiB 上限，并拒绝地址、凭据、代码等未知字段。名称标准化后忽略大小写比较，重名返回 `duplicate_name`；相同 UUID 和文本重试返回已有登记。目录与导入审计在一次提交中保存，空变更事件触发重新读取，最多保留 1,000 项。导入不会安装原生插件或验证连接；原通讯录丢失时拒绝用新目录替代已有数据。

正式组织由管理员在团队页面显式启用。首次配置向导展示部署中配置的公司与时区，要求审核当前成员的部门、岗位标签后，再将其采纳到独立的 `enterprise_office_organization` 第 1 版领域。`initializeOrganization` 核对审核过的通讯录修订号，不会重新初始化已有组织。`OfficeOrganizationUnit` 和 `OfficePosition` 使用不透明 UUID 及独立版本；`OfficeOrganizationAssignment` 将保留的员工关联到部门，以及全公司通用或限定部门的岗位。层级环、同级重名、过期编辑及不兼容岗位均被拒绝。停用前必须清除或调整在职成员归属，并停用启用中的下级实体。管理员保留停用历史，普通员工视图隐藏停用实体和归属。

`saveOrganizationUnit`、`savePosition` 和 `assignOrganization` 在共用写入队列中核查当前启用的管理员身份。个人资料修改不会改变正式归属，岗位也不赋予账户角色或文件权限。原成员 schema 和联系标签保留，用于既有记录及审核后成员编辑。组织通知不带业务内容，客户端重新载入有权视图。关闭整个 Host 时，存储设施级的排空屏障避免同级插件并行卸载时，在已接受的办公操作持久化之前关闭领域。

`drive`、`createDriveFolder`、`renameDriveEntry`、`saveDrivePermissions`、`uploadDriveFile` 和 `downloadDriveFile` 使用独立的 `enterprise_office_drive` 第 1 版单元。私有根目录按员工隔离，管理员也不能绕过读取。共享根目录默认员工只读、管理员可编辑；具体共享条目随后在每个祖先上逐层检查所有者、默认及账号条件。隐藏祖先会阻断子条目所有者的访问。授权使用管理员管理的员工编号，不使用可自行编辑的部门名称。同级名称忽略大小写，并遵循 Windows 文件名规则。修改要求当前版本，在共享队列中重新检查成员资格，目录与审计持久化成功后才发布事件。

网盘字节保存在 `DSH_HOME/office/drive/v1/objects` 下排他创建的不可变对象中，元数据记录服务端 UUID、大小和 SHA-256。字节 fsync 完成后才发布元数据；读取有大小边界，返回前核对大小及摘要。同一上传 UUID 与原内容重试会返回原条目，改变内容则冲突。备份需同时包含对象目录和配置的 `enterprise_office_drive` 存储单元。元数据写入失败可能留下不可达对象，自动回收继续待办，避免不确定提交导致已引用字节被删除。

<a id="company-connections"></a>
### 公司系统连接

可选的 `oa` 按本产品的 [OA 桥接 v1 协议](oa-bridge/README.zh.md)注册 `oa-bridge-v1`，显式配置私有员工映射和按角色允许的动作声明。省略配置时不启用，它不是现成 OA 厂商的内置 API。客户负责实现并联调桥接服务，包括认证、业务字段映射和按原标识持久恢复回执。现有连接策略、审核文本提交、私有执行历史及显式读取同步继续作为执行依据。

可选的 `wecom` 注册内部应用连接器，显式配置 `corpId`、正整数 `agentId`、办公员工到企业微信 UserID 的 `members`，并通过 `actions` 选择 `profile` 和／或 `send_message`。UserID 不区分大小写时仍须唯一，最多 64 个 UTF-8 字节；广播及多收件人值被拒绝。通过 `connectorAllowedOrigins` 批准 `https://qyapi.weixin.qq.com`，声明私有凭据别名，再保存适配器 `wecom`、该基础 URL、检查路径 `cgi-bin/gettoken` 及选择 **CorpSecret** 引用的 Bearer 认证。已批准的私有代理可保留基础路径。仅配置不会发起客户请求。

连接器遵循官方[令牌](https://developer.work.weixin.qq.com/document/path/91039)、[成员](https://developer.work.weixin.qq.com/document/path/90196)和[错误码](https://developer.work.weixin.qq.com/document/path/90313)定义。CorpSecret 仅发给 `gettoken`，取得的 access token 仅发给成员请求。单条、仅进程内缓存绑定应用、端点及当前凭据指纹，在服务端有效期前过期，提供方卸载时清空。显式检查连接会刷新认证。无效／过期令牌响应清除缓存并报告未授权；下次显式操作重新认证，不在当前操作中自动重试。令牌和原始密钥均不持久化。

`wecom-profile` 只查询当前认证员工的部署映射，并以不区分大小写方式核对返回 UserID。未映射员工不发请求。结果和同步只暴露姓名及可选岗位，继续受既有字节／条目上限约束；电话、邮箱、部门标识及平台诊断不对外披露。重定向、超大／非法 JSON、超时和应用错误保留实际失败状态。客户应用权限及网络仍需联调。资料查询不提供交互任务回调或企业 SSO。

企业微信 `send_message` 遵循官方[应用消息](https://developer.work.weixin.qq.com/document/path/90236)文本协议。员工只审核 `content`；连接器固定应用与本人收件人，在认证前拒绝超过 2,048 个 UTF-8 字节的内容，且任何请求前先持久预留原执行标识。消息标识回执只确认平台受理，不宣称送达／已读。明确的权限、收件人及限流失败被拒绝；缺失、格式无效或矛盾回执保持未知。核查原结果只读取该提供方发件箱，可在不再次请求的情况下恢复丢失的外层办公回执。不启用部门／标签收件人、广播或标识转译。平台内容窗口去重不能区分不同的已审核执行，因此关闭该选项，由原标识的持久预留防止重放。任务实体及交互完成回调仍是独立工作。

可选的 `dingtalk` 配置为企业内部应用注册 `dingtalk` 连接器。`appKey` 标识应用；`members` 将办公员工映射到不同的钉钉 `unionId` 及可选的显式 `calendarId`／消息 `userId`。`actions` 明确选择 `todos`、`calendar`、`create_todo`、`create_calendar` 和／或 `send_message`；消息还需 `robotCode`，员工标识不从 union-id 推断。未来日历窗口默认为 24 小时，接受 1–744 小时。通过 `connectorAllowedOrigins` 批准 `https://api.dingtalk.com`，通过 `connectorCredentials` 声明凭据别名，并将连接设为该基础地址、适配器 `dingtalk`、检查路径 `v1.0/oauth2/accessToken`，选择引用 **AppSecret** 的 Bearer 认证。秘密值保留在凭据提供方。批准的内部 API 代理可使用自身基础路径。

每次显式检查或查询解析当前 AppSecret，仅向令牌端点 POST 应用凭据，不保留令牌缓存。业务请求只携带获得的钉钉访问令牌头。提供方采用[阿里云官方 SDK](https://www.npmjs.com/package/@alicloud/dingtalk/v/2.2.48)中企业令牌、`QueryOrgTodoTasks` 和 `ListEvents` 的请求定义。查询使用认证员工的配置映射，不接受调用者填写钉钉身份。未映射员工及缺少日历映射时不请求客户系统。重复的 union-id 映射在配置准入时失败。

读取仅展示受限第一页的待办标题／状态或日程标题／时间，并提示是否还有结果；不遍历全部分页，不暴露参与人明细、提供方游标或诊断。既有同步仅保留这些脱敏的员工私有字段。拒绝重定向，错误／中止遵循办公请求限制。真实企业权限、凭据和连通性仍须客户联调验证。

`create_todo` 范围提供审核写入表单，包含 `subject`、可空的 `description` 和 ISO 8601 `due_time`。创建者和执行者固定为认证员工的映射；表单不能选择接收人或来源标识。无效日期和认证失败在发送任何任务 POST 前拒绝。原办公执行标识作为钉钉 `sourceId`；准确重试返回已保留的办公回执。任务 POST 开始后，缺失或无效回执保持结果不确定。“执行记录 → 核查客户处理结果”仅认证令牌，并用原标识 GET `GetTodoTaskBySourceId`。只有来源及创建者都匹配才确认创建；404 或身份冲突仍为不确定。原生审批和页面审核保留原有职责，不自动重复客户任务 POST。

`create_calendar` 范围审核 `summary`、可空的 `description` 和必填 ISO 8601 `start_time`／`end_time`。非递增时间区间及缺少私有日历映射在认证或业务派发前拒绝。事件仅指向配置的日历，明确不包含参与人，并在 SDK 定义的 `x-client-token` 头中发送原执行标识。成功须有日程标识及匹配的标题／时间。丢失或无效回执保持不确定。当前提供方不声明未知日程的权威核查；请保留执行标识并在钉钉查看日历。执行记录中的核查返回不可用，不产生另一次网络请求或日程 POST。

`send_message` 范围审核标题和 Markdown 文本，通过 `BatchSendOTO` 只向显式映射的本人员工标识提交 SDK `sampleMarkdown`。接收人、机器人及模板参数由服务端持有。提供方发件箱在令牌或机器人请求前持久预留原执行标识；准确重试及冷恢复不重复已预留的机器人 POST。回执报告平台受理及 `processQueryKey`，不声称送达或已读。无效／被过滤／被限流员工的明确结果分别保留。缺少回执保持未知，核查仅读取原提供方发件箱。提供方回执已持久保存时，可恢复写盘失败的外层办公回执，无需再次请求钉钉。

可信适配器可通过可选 `reconcileActions` 将核查限制到准确的已声明写入标识。登记时快照并验证清单；省略时保留原核查行为。不支持的动作返回既有不可用状态，不改变业务回执。此元数据不增加执行阶段，也不改变办公／原生持久化格式。

连接使用独立的 `enterprise_office_connectors` 第 1 版领域。`saveConnection` 要求启用的管理员身份、已登记集成、审核版本及稳定重试 UUID。一次提交同时保存配置及有长度边界的保存审计。写入失败不发布变更；准确重试返回已保存版本，竞争修改返回冲突。原办公、集成清单和 Session schema 不变。启动时拒绝脱离原目录或通讯录的连接数据。适配器或部署策略移除后仍可停用连接。

部署策略显式允许规范来源及连接器专用别名。例如办公插件配置可包含 `connectorAllowedOrigins: ['https://oa.company.example']` 及 `connectorCredentials: { 'oa-key': 'COMPANY_OA_TOKEN' }`。既有凭据提供方持有 `COMPANY_OA_TOKEN` 的值，连接配置只保存 `oa-key`，由办公服务端在每次操作时解析。集中部署使用中央服务端的凭据提供方，员工 Host 不解析它。本地文件提供方使值不进入办公 RPC 和浏览器视图，但不能与以同一 OS 用户运行的原生 Agent 进程隔离；需要这种隔离时应使用独立服务身份或其他凭据提供方。

`connections` 分别报告停用、缺少适配器、策略拒绝、凭据缺失／不可用或尚未验证。只有管理员接收可编辑地址、认证别名及策略选项。仅保存配置不代表已经连通。`probeConnection` 要求审核过的已保存版本及管理员权限。内置 `http-json` 适配器对相对探测路径发送 GET，拒绝重定向，只有完整且受字节上限约束的 UTF-8 JSON 响应才成功。单一网络／响应体期限覆盖慢响应。认证失败、限流、HTTP 失败、格式错误、超时和网络不可达分别返回状态；不返回响应内容或可能含密钥的诊断文本。探测占用共用办公队列，不自动重试或执行业务写入。结果只说明该次检查，不能授权后续操作。

受信任的 Host 插件可在所属 `ctx.effect` 中调用 `registerConnector`。移除适配器会中止正在执行的探测，使已保存连接不可用；适配器必须在中止后停止全部工作才结束。导入清单不安装适配器或凭据，原生 MCP 和插件管理继续独立。客户系统读写、员工映射及业务审计属于独立消费者。

适配器可声明有数量和大小上限的业务动作元数据，包括标识、名称、说明、读写类型和明确允许的角色。登记时复制并冻结声明。`connectorActions` 为当前已认证员工读取一个已登记系统，管理员没有隐式角色绕过权限。结果不包含角色策略、连接地址或凭据别名。读取不发起网络检查、不解析凭据值，也不执行动作。未配置或不可用的连接不返回动作。异步就绪读取期间更换提供方会返回 `conflict`。目录包含已保存的连接版本和进程内提供方版本，后者在替换或重启时变化；这些坐标不授予执行权限。

`readConnectorAction` 在核查当前员工的准确角色、审核过的连接和提供方版本后，查询一个已声明的读取动作。受信任适配器通过 `read` 显式接入；仅提供元数据的提供方和写动作不能通过此方法执行。服务端提供已认证员工、获准基础地址、即时解析的请求头和协作式期限。适配器必须完成员工映射、只执行读取、拒绝重定向并脱敏业务字段；中止后必须停止全部工作才结束。服务校验纯文本概要／字段，并限制完整 UTF-8 回执；格式无效、超限及迟到结果不暴露数据。提供方替换、关闭及会话过期都会阻止结果返回。网络失败分别报告状态。查询不更改办公业务记录、不自动重试，也不保留持久执行历史；员工页面仅暂存本次结果。任意查询参数、业务写入及原生 Agent 查询工具属于独立消费者。

可选的[原生办公工具](../tool-office/README.zh.md)使用绑定捕获的目录及读取操作。这些操作仅恢复提交员工自己的私有捕获，在使用已声明动作前比较当前角色、关联版本及捕获的连接版本。原生审批不会授予其他员工的捕获，也不会静默采用变更后的连接。真实查询字段沿用原生工具结果历史，办公服务不增加并行 Session 写入者。

<a id="message-provider-outbox"></a>
### 消息提供方发件箱

提供方拥有的 `enterprise_office_dingtalk_messages` 第 1 版单元保留原执行标识、员工／角色归属、绑定／内容 SHA-256 指纹及脱敏结果。`dingtalkMessageMaxEntries` 默认保留 1,000 次预留；`dingtalkMessageMaxBytes` 将完整 UTF-8 领域 JSON 限制为 16 MiB。容量满时仍可读取原重试，新预留及超大回执失败不替换原字节。消息正文、原始钉钉员工标识及凭据不属于此单元。

企业微信拥有独立的 `enterprise_office_wecom_messages` 第 1 版单元，复用预留机制并使用独立容量。`wecomMessageMaxEntries` 默认为 1,000，`wecomMessageMaxBytes` 默认为 16 MiB。其应用／端点／员工绑定对 UserID 不区分大小写；正文只保留指纹，确认结果中仅保存脱敏平台消息标识。共用预留代码保留钉钉单元原名称、版本和 schema。

并发预留仅在持久标记提交后授予一次派发许可。重启后未确认标记返回未知，不再次授予派发。办公所有者在存储工作前及披露前复核权限；提供方关闭后拒绝新操作，领域关闭前排空已接受写入。备份须同时保留消息单元和原员工通讯录，缺少通讯录时拒绝恢复激活。外部派发由已声明并经过审核的写入动作单独负责。

<a id="synchronized-read-records"></a>
### 同步读取记录

`OfficeConnectorView.synchronization` 声明持久读取快照能力。`syncConnectorAction` 接收审核过的已声明读取、连接／提供方版本及员工范围内的重试 UUID；先将实际脱敏结果原子保存到 `enterprise_office_connector_syncs` 第 1 版，再确认同步。认证、限流、不可达及响应失败保留实际状态，不返回结果字段。持久化失败不确认成功。已提交请求的准确重试返回原记录，不重复客户读取；从未提交结果的读取可以再次执行。

`connectorSyncPage` 最多返回 20 条本人元数据，不包含业务字段；向前锚点属于该员工及所选系统。`connectorSyncDetail` 返回历史字段前核对当前角色、允许的读取动作及未变化的已保存连接。提供方移除或权限变化会隐藏数据。新进程登记在连接未变且当前权限满足时可重新打开历史记录，原提供方坐标继续作为审计元数据。读取历史不请求客户系统；同步值是带时间的历史快照。

`connectorSyncMaxEntries` 默认保留 1,000 条记录，`connectorSyncMaxBytes` 默认限制完整 UTF-8 领域 JSON 为 16 MiB，不裁剪历史。备份同步单元及原员工通讯录、集成和连接；证据损坏或原公司记录缺失时拒绝激活。工作台同步控件由客户端消费者负责。

<a id="external-write-evidence"></a>
### 外部写入证据

对本人已派发／未知回执，**核查客户处理结果**明确读取原操作结果。可选适配器 `reconcile` 获得原服务端幂等标识、当前员工、即时私有连接及有限读取上限，不获得业务值，且不得重发写入。已保存连接版本必须仍与原操作一致；当前角色、提供方注册及来源会话再次核查。重新加载的受信任适配器仅可在同一已保存连接下核查旧操作，仍使用原协商结果上限。

`checkConnectorExecution` 返回回执及 `updated`、`unknown`、`unavailable` 或 `connection_changed`。仅严格权威成功／未接纳结果可以提交新的终态；记录缺失、超时及含糊结果仍为未知。不支持或已变化的连接不发起客户查询，终态回执不调用核查器。持久失败保留先前保守证据，重复核查可恢复它，不派发新的业务写入。私有 cause 不进入员工响应。历史 UI 在接纳的读取结束后才更新所选回执及小型列表行，并拦截账号／角色／系统／详情变化后的晚到响应。

独立的 `enterprise_office_connector_executions` 第 1 版保留私有意图及审计阶段。请求包含选定动作、准确连接／提供方版本、按员工隔离的重试 UUID，以及最多 32 个、每个最多 4,000 字符的平面文本值；可选捕获标识其原生提交。稳定指纹忽略对象键顺序，但拒绝改变参数。服务端生成独立执行 UUID。预留不授予业务权限，也不发起外部请求。

受信任的队列所有者先持久预留意图，再记录 `dispatched`，之后独立执行器才可发送。`dispatched` 和 `unknown` 均投影为结果未知，两者都不能再次派发；成功或明确拒绝需要权威证据。只有尚未派发的预留可以取消。准确的终态确认可重复读取，冲突结果会被拒绝。系统时钟回拨时，审计时间仍保持单调。

接纳会在保留字节预算中预留已确定的结果上限和最大审计信封，结果增长不会占用其他未结束请求的容量。策略变更后，每次请求仍保留原结果上限。持久失败不把新阶段报告为已保存；结果提交失败时，保留保守的已派发／未知证据。重启保留原标识，不重放副作用。指纹无效、历史不一致，以及原公司目录／系统目录丢失都会拒绝加载，不重置领域。

`connectorExecutions` 为当前已认证员工保留原有批量回执 API，不含原输入值及指纹，管理员没有私有归属绕过权限。网关不暴露原始预留、派发或完成修改。[决策记录](../../../.agents/notes/implemented/architecture/2026-10-17-external-write-evidence.zh.md)解释结果不明的边界。

工作台使用 `connectorExecutionPage` 及明确的 `connectorExecutionDetail` 读取。`OfficeConnectorView.executionHistory` 声明协议 1 和完整响应上限。每页至多包含 20 个小型回执摘要及 32 KiB UTF-8 JSON，不含业务结果和审计数组。更早页游标为最后返回的服务端执行 UUID，必须属于当前员工及选中系统；新增提交不会使之后的旧页重复记录。详情上限为 4 MiB 加 4 KiB 信封，保留权威结果及有序审计阶段，解除适配器后仍可读取。

进入**集成 → 系统详情 → 执行记录**，可浏览本人的提交、明确加载更早记录或查看回执。未知结果与成功、明确未接纳分开显示，并保留执行标识以便核查。浏览不会调用客户适配器，也不会重新提交操作。账号、角色、系统、关闭及连接重置会拦截晚到的页／详情响应；详情读取在等待新结果前清除旧结果字段。客户系统的具体核查语义由已安装适配器负责。

声明写动作且实现已安装后，系统详情提供**填写并提交**。员工仅填写声明的文本字段，确认前核对准确系统、动作及值。模糊响应后，表单保留原内容及重试 UUID。明确重试原请求可能接纳从未到达的请求，但不能再次派发已经发送的操作。已返回的未知回执提供历史查看入口，不再提供提交按钮。配置变化阻止新的发送，不采用新的权限；账号／角色变化清除私有草稿并拦截回执。[工作台参考](../../client/ui-office/README.zh.md)负责这些表单，它们不向原生 Agent 历史添加消息。

`writeConnectorAction` 是明确安装了适配器 `write` 实现后的封闭提交入口，`writeSupported` 声明此可选能力。写动作可定义至多 32 个名称唯一的 `fields`，包含稳定名称、公共标签、必填标记及长度上限。未知、缺少必填及超长值在预留前拒绝。当前角色、准确提供方／连接版本及可选私有提交捕获在派发前再次核查。凭据在 Host 即时解析；适配器仅获得已认证员工、核对值、获准连接及用作外部幂等键的服务端执行标识。中止后必须停止工作才结束，且不得自动重试。

仅严格、有上限的权威 `succeeded` 或 `rejected` 结果可结束操作。超时、卸载、无效输出及派发后缺陷保留未知证据。`execution_unknown` 提供稳定公共处理身份，私有 cause 保留后端诊断。回执提交后才返回成功，结果提交丢失不能触发再次派发。提供方解除后，准确的已结束重试仍可读取。同员工／系统／动作／输入即使更换 UUID 及临时连接坐标，也返回原未决回执。可选[原生工具消费方](../tool-office/README.zh.md)提供独立写审批和真实工具回执，员工表单使用同一协调器，客户系统的具体核查语义由已安装适配器负责。

### 可续传网盘传输

`beginDriveUpload` 在独立的 `enterprise_office_uploads` 第 1 版领域创建仅所有者可见的票据。声明固定目标位置、名称、大小、SHA-256 和重试 UUID。`appendDriveUpload` 接收有边界的规范分块，重新检查启用成员、已认证会话、所有祖先及额度，仅在回执持久化后确认接收。`driveUploads` 列出员工未完成票据，`getDriveUpload` 在响应丢失或重启后恢复回执位置。配置变更后，票据仍保留原协商分块大小。

`completeDriveUpload` 在发布目录前校验所有分块及完整摘要。发布和回执确认是分别进行的持久写入，相同重试可在回执丢失后恢复已发布文件。已引用版本和未完成声明共用员工额度，已发布的重试身份从待完成预留中排除。`cancelDriveUpload` 先持久化终态决定，再回收暂存内容；已发布文件返回完成状态并保留。过期清理在启动、上传操作及配置的计时器中运行。清理失败保留记录并重试，过期未完成记录在清理成功前仍占预留额度。终态回执按配置保留。回收仅处理台账所属暂存内容和未发布对象，原目录及办公领域结构不变。

`driveFileInfo` 在返回版本和下载边界前授权并校验完整不可变对象。`downloadDriveRange` 将每次有边界读取固定到该版本，并重新检查成员和祖先可见性。每个响应包含分段摘要，消费方在保存前校验完整文件摘要。这些方法也能读取已有整请求上传对象。整请求上传／下载 API 保留 8 MiB 边界，可续传限制通过 `OfficeDriveView.transfers` 分别声明。

### 私聊文件

`chatFileLimitsFor` 返回当前发送人的策略及保留逻辑用量。`sendMessageFiles` 接收一条含有序文件和可选说明的内联消息；协议限制解码后文件合计为 8 MiB，独立于网盘续传上限。默认允许五个文件，发送人独立额度为 256 MiB。相同 UUID 和内容重试复用原文件及消息；复用标识却改变文本、接收人或字节会被拒绝。说明为空时显示文件名。

独立的 `enterprise_office_chat_files` 第 1 版领域先记录服务端分配的文件标识，再将字节写入 `DSH_HOME/office/chat/v1/objects`。文件完成核验及 fsync 后进入就绪状态，随后提交原文字聊天消息头，由该消息头决定是否发布。最后回执写入失败时依据已提交的消息头恢复。文字接口不能发布未完成文件声明占用的消息标识。既有聊天和 Session schema 不变；授权视图添加可选附件元数据。

`downloadChatFile` 要求操作者为仍启用的原消息发送人或接收人，完整核验文件后才返回字节。管理员不能绕过私聊范围。发送人停用后，启用的接收人仍可下载历史文件。原通讯录缺失、聊天水位丢失或发布不一致时拒绝启动，不会重新初始化或回收已引用文件。启动、发送及所属定时器只清理本账本指名的过期未发布对象；清理失败保留预留额度并重试。备份需同时保留原聊天、文件声明领域和不可变对象目录。内联传输不提供网络分块续传接口，发送失败时使用完整原内容重试。

### 私有文件草稿持久化

`chatFileDrafts` 只返回启用员工本人的联系人版本、文件元数据及草稿额度。`saveChatFileDraft` 在 `enterprise_office_chat_file_drafts` 第 1 版领域中原子替换已审核选择；相同 UUID 和内容重试保留原标识，过期版本冲突，清空文件保留版本墓碑。`downloadChatFileDraft` 只向所有者恢复当前审核版本的文件。预定接收人和管理员均不能查看未发送草稿。可清除停用联系人的选择，不能向其保存新文件。

此受限领域将规范 base64 字节与大小及 SHA-256 一同保存，可原子更新草稿而不产生无引用的文件系统对象。草稿遵循聊天消息的文件／数量／合计限制，并使用独立逻辑额度：默认每位员工 16 MiB、全公司 128 MiB。Base64 比解码后字节多占约三分之一空间，保存会重写此存储单元；更大的二进制存储需独立提供方。既有文本草稿和已发送文件对象保留各自 schema 与存储。备份时需将该草稿领域视为员工私有数据保留。

`sendChatFileDraft` 先持久化准确说明、审核版本及消息 UUID，再通过原不可变文件消息流程发布。只有确认的原选择会被清除，并保留发送回执。清除或响应失败时依据原消息恢复，启动时同样执行，不会重复发布或清除新草稿。未解决发送阻止无关编辑，并在本人元数据视图中保留原重试输入。草稿变更事件不含内容。通讯录缺失、字节损坏或原聊天水位丢失时拒绝继续；关闭时等待已接收草稿写入完成。浏览器流程由独立 UI 包负责。

空的审核选择会显式清除原文件草稿，包括未解决的发送。队列先保留任何已提交消息，迟到的草稿发送重试不能恢复已清除版本。部署额度降低到保留用量以下时仍可清除。停用联系人要求本人已有对应草稿记录，保留版本可授权只读空会话，不向无关员工暴露停用成员。公开草稿元数据包含获准查看的联系人身份，不广播字节或其他员工草稿。未发布的发送文件预留继续使用既有过期及清理策略。

<a id="conversation-associations"></a>
## 会话关联

`conversationLinks` 仅读取当前员工在逻辑原生会话中已审核的选择。`saveConversationLinks` 使用展示版本和稳定重试 UUID 编辑工具或集成列表。两项操作均保留原生 Session 历史，不向 Agent 发送请求或执行能力。逻辑会话编号属于已认证员工的命名空间，其他员工及管理员读取同一编号时得到各自的空选择。同一员工在不同 Host 中主动复用同一逻辑编号时，共享该关联草稿。

`conversationToolDependencies` 使用 `skill:office-review`、`template:minutes` 等键，映射到所需集成清单的 `name`。名称匹配执行 Unicode 标准化并忽略大小写，不依赖翻译后的系统显示标签。读取结果区分匹配编号和缺失登记名称。保存工具列表时自动加入当前已登记依赖；显式编辑集成列表可以移除依赖而保留工具，消费者需展示尚未关联状态。已登记依赖仍可能未配置、停用或不可用，选择及登记解析均不授予执行权。

独立的 `enterprise_office_conversation_links` 第 1 版领域保留私有选择版本，包括空墓碑。准确重试返回已接纳的原版本，过期编辑产生冲突；存储失败不发布版本或失效通知。共用办公队列重新检查当前启用状态及登录会话有效性，关闭时等待已接收写入完成。配置选择上限降低到保留用量以下时仍允许严格移除。保留会话记录已满时返回 `conversation_capacity`，清空选择不会抹掉版本或释放该记录位置。选择损坏或原通讯录／集成目录缺失时拒绝启动，不替换历史。备份需同时包含选择领域、企业通讯录和集成目录。

<a id="prepared-contexts"></a>
### 准备上下文

`captureConversation` 在 `enterprise_office_conversation_captures` 第 1 版中冻结员工审核的关联版本、所选系统元数据、声明依赖及当前配置就绪状态。输入为逻辑会话编号、审核版本和原生提示词的不透明请求编号（1–512 个可打印字符）。返回的 `OfficeConversationCapture` 是准备元数据，不证明原生提示词已接纳、模型已调用或能力已执行。即使操作者是管理员，也不复制可编辑连接地址、认证字段、凭据别名或密钥值。配置就绪与网络检查成功保持独立。

准备操作按员工、逻辑会话及原请求编号保持幂等，不同会话可复用 SDK 请求编号。准确重试在应用当前保留上限或重新读取已改动选择之前返回原上下文，同一键的审核版本改变则冲突。服务端另发 UUID 供 `conversationCapture` 恢复，该接口仅返回当前启用员工自己的记录，管理员没有绕过权限。

写入使用共用认证队列，关闭时等待已受理写入完成。快照携带按声明字段顺序生成的紧凑 UTF-8 JSON 的 SHA-256 摘要，排除 `digest` 字段；该完整性值不是授权凭据。记录损坏或原员工数据缺失时拒绝启动，不重新播种。备份需包含快照及原办公通讯录。

准备操作保留已接纳的证据，不隐式过期删除。新记录达到配置的数量或保留字节上限时返回 `conversation_capacity`；单个上下文过大返回 `context_too_large`（HTTP 413），调用方可减少选择。降低上限不删除旧记录，也不阻止准确重试或读取。保留字节统计领域值的紧凑 JSON，含请求坐标和指纹；提供方格式及存储开销单独计算。原生提示词附加及执行约束是这项准备 API 的独立消费者。

`conversationFiles` 与 `saveConversationFiles` 分别为员工和逻辑会话保留独立的已审核网盘选择。客户端只提交不可变文件坐标，服务端确认名称、大小、类型及摘要。独立的 `enterprise_office_conversation_files` 第 1 版领域每个选择最多包含 20 份不同文件，最多保留 10,000 个选择及 10,000 份准备快照，紧凑 JSON 上限为 64 MiB。现有集成／工具选择、快照、网盘元数据及原生 Session 各代格式不变。备份包含新领域、原通讯录、网盘元数据及不可变对象。

`captureConversationFiles` 根据已审核文件版本和原生请求身份冻结私有描述证据。后续选择修改不改变准确重试返回的原快照，但重试仍检查当前角色、文件权限及最新不可变版本。`conversationFilesCapture` 仅向原所有者且当前角色匹配的账号恢复证据。`readConversationFile` 从最多 1 MiB 的已校验 UTF-8 文件读取，接受最多 16,384 个 UTF-16 码元的预算，在补齐末尾代理项对后返回下一偏移。每次读取都检查已选文件、员工启用状态、角色、祖先 ACL、最新版本及 SHA-256。编码无效、含二进制 NUL 或越权时不返回内容。原生提交上下文及 Agent 工具暴露是这些 API 的独立消费者。

`readConversationPdf` 从已提交 PDF 的指定一页提取可选文本，并执行相同的当前所有权、角色、祖先权限、版本及 SHA-256 检查。`conversationPdf` 配置输入字节数（8 MiB）、文档页数（200）、单页提取字符数（262,144）、完整原生工具内容 JSON 字节数（64 KiB）、worker 期限（5,000 毫秒）及 V8 老年代堆（128 MiB）。完整分配或创建 worker 前先检查输入大小。每次隔离解析使用空环境，关闭 PDF 代码求值及外部字体／图像加载，并在操作结束前终止。取消及关闭会终止解析。末次权限核查和有界结果在同一办公队列内完成。解析不保留完整文档缓存或原生附件副本；损坏、加密或超限文件不返回文本。扫描页可能返回空文本；OCR 及版面重建属于独立工作。

`readConversationDocx` 提取真实 `.docx` 主文档正文段落及按源顺序排列的表格单元格。制表符分隔单元格，换行分隔段落和表格行，不把合并单元格展开为矩形网格。页眉、脚注、批注、域指令、已删除文本及绘图不在提取范围，外部关系不会被跟随。读取器要求标准的内部 Word 主文档部件，拒绝损坏 XML、DTD／实体声明和宏文档内容类型。不执行分页或 OCR，不读取旧 `.doc`、电子表格或演示文稿。

`conversationDocx` 配置压缩输入字节数（8 MiB）、含跳过媒体的 ZIP 条目数（1,024）、全部条目声明的解压字节数（32 MiB）、每份已解析 XML 部件字节数（8 MiB）、访问 XML 节点数（100,000）、提取的 UTF-16 码元数（1 Mi）、转义后完整原生工具内容 JSON 字节数（64 KiB）、worker 期限（5,000 毫秒）及 V8 老年代堆（128 MiB）。服务端在完整分配或创建 worker 前检查输入大小，并在解析前校验真实字节及 SHA-256。每次读取使用空环境的一次性 worker；取消、超时及关闭会在操作结束前终止它。末次归属、角色、祖先权限及版本检查和有界结果在同一办公队列内完成。不保留完整文档缓存或原生附件副本，解析失败及超限均不返回正文。

`readConversationXlsx` 读取 `.xlsx` 的保存单元格，不重新计算公式。`sheetNumber` 从 1 开始按工作簿顺序排列，不依赖工作表标识；`offset` 按行／列顺序统计已存单元格，包含显式空白。每次最多返回 `maxCells`（1–256）个单元格，以及有界的工作表目录、地址、隐藏表／行／列状态和连续读取坐标。稀疏空洞及合并区域不会生成单元格。数字与日期序列在 `value` 和 `rawValue` 中保留准确的 XML 词面字符串；`dateSystem` 指明 1900／1904 纪元，`numberFormat` 提供保存格式，不执行视觉格式化。共享字符串的 `rawValue` 是保存的字符串表索引，布尔值在此保留 `0`／`1`。XML 字符串实体只解码一次，不用 JavaScript 数值近似替代源金额或序列值。

公式证据保留原 XML 文本、类型、共享索引及范围，不把共享引用展开为虚构表达式。`cacheState` 区分 `missing` 与 `present_may_be_stale`，包括已存的零、false 及空字符串结果，不把保存结果报告为重新计算。[OOXML 单元格值](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cellvalue)定义保存值及公式缓存；[ExcelJS](https://github.com/exceljs/exceljs#formula-value) 不计算公式。读取器拒绝宏内容、VBA、外部工作簿依赖、数据连接、DTD／实体声明及有歧义的包部件。超链接仅返回既有显示文字，不返回或访问目标。图表、绘图、图片、批注、数据透视表、Table 样式、旧 `.xls`、`.xlsb`、`.xlsm` 和加密工作簿不在此读取器范围内。

`conversationXlsx` 限制压缩字节数（8 MiB）、全部 ZIP 条目数（2,048）、含跳过媒体的声明解压总量（32 MiB）、每份 XML／关系／VML 部件（8 MiB）、XML 节点数（500,000）、工作表数（32）、全部表内已存单元格数（100,000）、提取的值／原值／公式／格式／名称（1 Mi 个 UTF-16 码元）、转义后完整原生工具内容 JSON 字节数（64 KiB）、worker 期限（5,000 毫秒）及 V8 老年代堆（256 MiB）。ExcelJS 加载工作簿前先核对 ZIP／XML 预算，其有界临时解析副本去除 DrawingML 和二进制媒体，仅存在于 worker 内。服务端在完整分配前检查输入大小，在创建空环境 worker 前校验真实字节及 SHA-256，并在失败、取消、超时或关闭时等待 worker 终止。末次归属、角色、ACL 及最新版本核查与完整结果上限处于同一办公队列，中间没有 await。某个单元格或目录无法放入预算时不返回结果，值和公式均不截断。不保留完整文档缓存或原生附件副本。

`readConversationPptx` 按源顺序读取 `.pptx` 已保存的形状文字、分组形状和表格单元格。`slideNumber` 从 1 开始按演示文稿关系表排序；`section` 必须明确选择 `slide` 或 `notes`。备注不会自动附加，备注中的页码、日期、页眉、页脚和幻灯片图像占位符会被排除。结果包含有界的幻灯片目录及隐藏／备注标记、所选部分的段落／表格／隐藏形状数量、已校验文件元数据、`text`、`nextOffset` 和 `eof`。隐藏形状文字仍会保留。UTF-16 窗口不超过 `maxCharacters`（1–16,384），会退回到代理项对之前；无法容纳下一个完整字符时失败。图片、图表、SmartArt、母版／版式文字、附件、视觉布局、OCR 和旧 `.ppt` 不在范围内；宏、损坏关系和不安全 ZIP／XML 不返回文字。外部超链接只作数据。

`conversationPptx` 为可选配置，省略时关闭。启用时必须显式提供全部上限：`maxBytes`、`maxArchiveEntries`、`maxInflatedBytes`、`maxXmlBytes`、`maxNodes`、`maxSlides`、`maxTextCharacters`、`maxOutputBytes`、`timeoutMs` 和 `workerMemoryMb`。这些上限覆盖完整分配前的压缩输入、含忽略媒体的全部声明解压字节、每份已解析 XML、访问节点、全部有序幻灯片及其正文／备注文字，以及含文件和目录元数据的完整转义原生结果。每次真实读取在空环境 worker 前校验提交归属、当前员工／角色、祖先 ACL、最新不可变版本和完整 SHA-256；发布有界结果前，在同一队列内再次核查当前权限及版本。取消、超时和卸载会等待 worker 终止；不保留完整文档缓存或原生附件副本。

可选的 `conversationFiles.pdf.maxBytes`、`conversationFiles.docx.maxBytes`、`conversationFiles.xlsx.maxBytes` 与 `conversationFiles.pptx.maxBytes` 能力分别允许在当前服务输入上限内选择对应格式；省略某项能力则该格式不可选。不提供这些能力的旧服务继续只允许文本选择。原生工具消费者保留既有审批及持久结果管线。

<a id="agent-work-execution"></a>

### Agent 工作执行

`createWorkFromConversation` 接收 `OfficeAgentWorkInput`：UUID 执行重试编号、私有准备快照及普通任务／待办字段。它仅创建内部办公事项及已有的负责人通知，不向外部公司系统发送请求。新写入要求员工及负责人启用、快照归属原员工且角色仍一致、审核关联版本相同，并选中 `template:reminder`。当前声明依赖必须与快照一致、已登记且仍保持关联；必需连接须启用、满足部署策略、适配器可用且版本与捕获时一致。就绪状态不代表外部送达成功。

独立的 `enterprise_office_agent_work` 第 1 版领域会在普通工作提交前，先预留服务端生成的事项 UUID。预留持久化失败时不写业务事项；之后业务写入或确认失败时，准确重试使用同一预留编号，不再次建单。待完成预留在新写入前复核当前权限，包括预留落库期间适配器卸载的情况。已完成重试即使在取消关联后，也仅按当前读取权限返回原事项，不再次执行。`OfficeAgentWorkReceipt` 返回请求坐标、预留时间及当前有权查看的事项状态。同一执行编号改变载荷会冲突。

保留字节统计包含工作字段及指纹的紧凑预留 JSON；降低上限不阻止准确重试。容量满时返回 `conflict`，不产生新业务写入。备份需同时包含本领域、工作数据及准备快照。指纹损坏或原员工目录丢失时拒绝启动。共用办公队列及关闭排空机制负责预留和业务发布。[预留机制决策](../../../.agents/notes/implemented/architecture/2026-10-17-office-agent-work-reservations.zh.md)解释两次提交之间的恢复。原生模型工具暴露属于单独消费方，普通人工创建工作继续使用已有 API。

<a id="drive-version-history-and-recovery"></a>
### 网盘版本历史与恢复

`OfficeDriveView.lifecycle` 表明服务支持审核式文件替换、版本历史和软删除。上传可选 `target` 将文件标识和修订号与当前名称、位置绑定。有权编辑者可提交新版本，原所有权及条件保留。每个分块和最终发布都重新检查当前访问权及审核版本。历史和删除版本继续计入文件所有者额度；其他编辑者的待提交替换也预留同一所有者额度。准确重试包括替换目标并保留原标识。`driveHistory` 返回新版本在前的元数据，不含上传重试凭据；`driveVersionInfo` 核对指定对象的完整性，`downloadDriveRange` 对每段历史读取重新授权。

`changeDriveLifecycle` 要求所有权、当前父目录编辑权及审核过的修订号。删除文件夹会隐藏所有后代，保留记录与字节。`driveTrash` 仅通过当前可见父目录列出本人的删除根条目。恢复保留标识、条件和版本；同级名称冲突时拒绝，所有者可提供合法新名称。这些操作保留既有 Native 会话及已交付文件数据。向共享存储写入替换或清理回执前，先阅读[版本升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-drive-versions/guide.zh.md)。

`drivePurgePlan` 审核完全属于调用者的删除子树，排除已经完成的清理范围。经 `purgeDrive` 确认时须提供相同修订号及摘要、稳定请求标识，并仍有父目录编辑权。服务先持久保存不可撤销授权，再 unlink 自有网盘的不透明对象；Native 路径不作为删除目标。失败保留待完成回执、禁止恢复并继续计入字节额度。`drivePurgeStatus` 读取所有者的既有回执；`retryDrivePurge`、启动恢复及 `drivePurgeSweepMs` 维护只继续既有授权。准确重试确认具有幂等性。只有完成记录持久成功才释放字节额度；保留的审计墓碑仍受元数据数量上限约束。`OfficeDriveView.quota` 返回员工已用、预留及配置字节额度。浏览器确认流程由独立 UI 包负责。

## 模型体验

### 员工业务数据

#### 模型看到什么

`enterprise_office` 领域不注册工具，也不增加提示词或 Session 事件。[员工 BFF](../../client/ui-office/README.zh.md)将提交的办公上下文写入日志，独立的[原生工作工具](../tool-office/README.zh.md)消费它以创建经过授权的内部工作。

直接 token 消耗为零。单独读取或修改办公记录不会调用模型。

办公数据修改不改变模型请求历史或可复用前缀。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待办

- 本服务提供密码认证基础操作，由独立网关负责网络入口；SSO、目录同步和多因素认证继续待办。
- 当前存储单元和写入序列只有一个 Host 所有者。多个 Host 并发写入需要事务提供方或集中服务，共享 JSON 文件不能实现这种协调。
- 整单元提交成本随历史增长。聊天读取已支持游标分页；工作列表分页、保留策略和可扩展企业存储仍待实现。
- 管理员审计检索覆盖六类已保留操作历史及四个已认证变更 RPC 的拒绝台账。其他拒绝授权、私有外部执行阶段及用量核算尚未聚合。身份、组织和连接历史各最多保留 1,000 条；导出无法恢复已丢弃记录。
- 整请求文件传输和聊天文件保留 8 MiB 边界。网盘续传服务默认单文件 64 MiB、文件所有者额度 256 MiB 且均可配置，浏览器流程由独立 UI 包负责。旧整请求上传孤儿对象的通用回收继续待办。永久清理保留元数据及审计墓碑，并遵守既有目录数量上限。
- 日程限于同一本地日期。重复日程、自动提醒、外部日历忙闲／发送、时间预留和跨日事件属于后续工作。
- 本包提供办公记录、可配置连接探测、已声明业务读取及受控写入协调器，独立 UI 包提供经审核的业务表单；群聊及客户适配器联调仍待实现。外部写入账本本身不授予执行权限。
- OA 桥接 v1 需要客户桥接服务及真实的 API、身份和授权约定。适配器接受声明过的文本字段，不包含附件上传、任意单号查询、审批决定、回调或自动同步。提交受理回执不代表业务审批通过。

<a id="dev-note"></a>
### 开发备注

同一服务实例对每个传输文件的发布串行处理，直到临时句柄关闭并清理完成；不同文件使用独立队列。准确重试校验已完成对象，失败的发布会释放后续尝试，同时向原调用方保留失败。Windows 队列身份包含大小写等价路径。跨进程改动仍接受排他发布及原有大小、摘要、文件身份和元数据检查，检测到变化仍报告冲突并要求重试。

领域清理在初始化打开第一个句柄前注册。已完成的打开均明确归属本服务；卸载后迟到的句柄在发布服务前关闭。关闭仍等待已受理修改，即使其他领域关闭失败也尝试关闭每个归属句柄。组合测试覆盖第一次打开延迟期间卸载，并在同一存储设施中重新启用。
