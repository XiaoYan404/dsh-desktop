# 原生办公工具

[English](README.md) | 中文

## 概述

提交提醒关联后，可以创建内部任务和待办，也可读取或提交当前会话选中公司系统所声明的业务操作。当前员工权限和原生审批保护执行。已确认工作保留在工作台中，真实查询结果和持久业务回执进入原生历史。未提交办公上下文的原生运行继续使用已有行为。

网盘可选图片、授权知识库和办公交付检查的配置、权限、保留及限制见[网盘读取参考](../office/drive-readers/README.zh.md)。

<a id="configuration"></a>
## 配置

企业工作台补丁启用本插件，标准 Web 组合保持停用。`approval` 默认为 `manual`，在办公创建前加入已有的原生审批请求。`automatic` 不额外加入该请求，继续交给其余原生策略链。已有拒绝和审批决定仍具有约束力。

`readApproval` 独立控制远程业务查询及已提交公司文件的读取，默认 `manual`。`automatic` 只跳过额外的读取确认。动作目录发现不发起远程业务请求，并继续遵循其他原生策略。

`writeApproval` 独立控制客户业务提交，默认 `manual`，即使内部工作或读取使用自动模式也是如此。`automatic` 只省略额外的业务写确认，其他原生决定及服务端授权仍然有效。

`pptx` 默认为 `false`，保留原有文件工具集合。设为 `true` 后，在提交文件的轮次提供 `office_read_pptx`；提供服务的办公权限端还须独立启用完整的 `conversationPptx` 策略。启用此消费者不会授予权限或自动审批。

<a id="execution"></a>
## 执行

认领了 `office` 或 `office-files` 提交上下文的存活 Agent 归属于最初的员工。没有办公上下文的 Steering 不能移除这项归属。子 Agent 继承员工和角色快照，父运行结束后仍保留该快照。同一员工的新提交可重新确认已变化的角色；另一员工不能接管该存活 Agent。描述性 capture 不授予执行权限。

每个模型步骤前及每次获批原生工具派发前后，插件检查已认证办公连接、当前员工和角色、准确存活 Agent 及插件生命周期。账号替换、退出、停用或角色变化会阻止后续准入，并拒绝交付迟到的最终工具结果。先前已接纳的操作可能已经提交，重试前需核查原结果。

具有办公归属的原生模型流在派发前及每个分片发布前复核当前权限。检查失败会关闭上游迭代器；被拒分片不进入实时助手发布或已提交的尝试记录。此前在授权有效时已发布的内容仍保留在历史中。未关联办公及辅助模型调用沿用既有流式行为。集中部署下，这些检查可能增加办公连接请求；原模型请求、输出分片及取消信号保持不变。

仅供 Host 使用的 `officeRunOwnership` 投影从原生输入和继承事件重建员工归属，覆盖插件重载和 Agent 恢复。其缓存状态版本为 3；缓存只是事件折叠的捷径，不是授权凭据。待处理输入会固定员工身份，但不能改变当前工作的角色；角色审核在该输入被认领时才生效。跨员工混合历史继续受限，原始事件记录保留。较早的权限失败后，可按原生驱动既有队列行为通过明确后续输入继续处理待审核工作。

[员工 BFF 检查具有归属的历史读取](../../client/ui-office/README.zh.md#understand-the-implementation)，独立于办公工具是否启用。本插件的运行守卫继续负责模型及工具准入。

在具有办公归属的 runtime parent 或作用域父运行下创建子 Agent 时，会在接受工作前记录 `office/run-inherited`。记录保存员工、角色及限制，不保留父对象；父运行退出后，冷恢复仍可重建归属。该记录不授予权限，也不进入模型历史。不认识这一必读事件的读取器会拒绝该子会话日志。没有办公归属或继承记录的历史后代，无法在父运行缺失时重建其归属。

已提交的网盘引用仅向当前轮次中准确运行的 Agent 提供 `office_read_file`。参数为已选 `file_id`、UTF-16 偏移 `offset` 和 1 至 16,384 的 `max_characters`。人工审核展示文件名、标识、版本、SHA-256、员工及完整读取窗口。每次实际读取都复核启用员工、捕获角色、祖先权限、准确的最新版本及摘要。UTF-8 文件上限为 1 MiB，二进制或编码无效时不返回正文。结果包含已校验元数据、纯文本、`next_offset` 和 `eof`。后续修改选择保留原提交快照，撤回权限仍会阻止读取。停止、销毁或卸载会阻止迟到正文进入结果，字节不会复制到原生附件存储。

`office_read_pdf` 从已提交 PDF 的指定一页读取真实可选文本，并采用相同的原生读取审批和存活 Agent 核查。参数包括 `file_id`、从 1 开始的 `page_number`、页内 UTF-16 偏移 `offset` 及 `max_characters`。审批在不可变文件元数据之外展示准确页码及读取窗口。办公服务拥有可配置的字节、页数、文本、worker 内存、期限及完整原生内容 JSON 上限。`nextOffset` 和 `eof` 表示当前页内的连续读取，不执行 OCR。准确元数据和文本进入原有 `tool/result` 及下一次模型请求。停止、销毁及卸载会取消解析，不缓存完整文档或原生附件副本。扫描页可能没有文本；加密、损坏及超限 PDF 返回不含正文的稳定失败。

`office_read_docx` 通过相同作用域的原生审批及结果流程读取真实 `.docx` 正文段落和按源顺序排列的表格单元格。`file_id`、UTF-16 偏移 `offset` 和 `max_characters` 指定准确的已审核文件及读取窗口。结果包含不可变元数据、段落／表格数量、`text`、`nextOffset` 及 `eof`；制表符分隔单元格，换行分隔段落和表格行。[办公服务](../office/README.zh.md#prepared-contexts)负责 ZIP／XML／文本、worker、完整结果上限及办公队列内的末次权限检查。原生取消传到一次性解析器。正文是不可信数据；页眉、脚注、批注、绘图、旧 `.doc`、分页及 OCR 不在此读取器范围内。

`office_read_xlsx` 通过相同的原生读取审批、存活 Agent 核查及准确 `tool/result` 日志读取保存的电子表格单元格。`sheet_number` 从 1 开始按工作簿顺序排列；`offset` 和 `nextOffset` 统计该表内已存单元格，`max_cells` 为 1–256。审批展示准确的不可变文件、工作表及单元格窗口。结果包含有界工作表目录、带类型的单元格、地址、隐藏状态及 `eof`。数字金额与日期序列保留 XML 原始字符串，结合 `dateSystem` 和 `numberFormat` 解释。公式文本只作数据，`cacheState` 区分缺失缓存与可能陈旧的保存结果，包括零及 false。不重新计算、不刷新外链、不执行宏。[办公服务](../office/README.zh.md#prepared-contexts)负责归档检查、worker 生命周期、取消、末次权限及完整 JSON 上限，不会为适应结果预算截断公式或数值。

`office_read_pptx` 通过相同的原生读取审批、准确的存活 Agent 和持久结果流程读取已保存的演示文稿文字。它要求 `file_id`、按关系表排序的 `slide_number`、显式 `section`（`slide` 或 `notes`）、UTF-16 偏移 `offset` 和 `max_characters`。审批展示不可变文件／版本／摘要、员工、幻灯片、内容部分和窗口。备注保持独立，不会自动请求。结果包含有界幻灯片目录、隐藏／备注标记、已保存的形状／分组／表格文字、数量和部分内连续读取坐标。[办公权限端](../office/README.zh.md#prepared-contexts)负责显式归档／XML／文本／worker／输出上限及解析前后的当前授权。不执行渲染、OCR、宏、附件或外部获取；已保存的演示文稿文字是不可信数据。

捕获的提醒依赖须已登记、保持关联且完成配置，才会提供工具。每次新的用户输入绑定自己的捕获上下文。注册归属该 Agent，在轮次结束、销毁或插件卸载时移除。省略 `owner_id` 时默认分配给提交员工，也可提供已知的启用员工编号进行分派。日期和工作字段由办公服务校验。

审批从原生调用的不可变参数中展示工作类型、标题、本地日期及时间、负责人编号和完整说明，省略负责人时也会显示提交员工。带引号的值将内嵌换行与字段标签区分开。长内容在原审批卡内滚动。其他原生策略的审批原因及语言条目会与这些字段共同保留，在办公自动模式下同样如此。确认不会改写参数。

执行必须属于当前准确的运行驱动。新写入前，办公服务检查快照归属、当前角色、审核选择、必需连接版本及当前可用性。原生调用与快照共同推导稳定的执行 UUID，重试同一调用会核对原事项。规范结果包含事项编号、负责人、状态及请求坐标。[办公参考](../office/README.zh.md#agent-work-execution)负责持久化及重试语义。

选中且已配置的系统会在对应 Agent 作用域提供动作发现及读取工具。发现仅返回当前角色允许的元数据和准确连接／提供方版本。读取要求这些审核坐标；审批显示实际系统、登记名称、动作标识、员工及版本。办公服务重新核查私有捕获、当前角色、当前关联、连接及提供方。取消关联或更改审核过的连接会拒绝执行，不采用新的权限。读取不接受其他员工、地址、凭据或任意查询参数。真实且有大小上限的纯文本结果沿用原生工具结果日志，并进入后续模型请求。网络失败状态不含业务字段；再次显式调用会重新查询。

意外的 BFF 基础设施失败对外返回稳定的办公服务错误，并保留私有 cause。适配器、凭据提供方或存储的原始诊断不会成为原生工具结果文字。写入结果不明时，重试前必须核查原操作；此边界不报告成功，也不回滚已提交工作。

`office_write_action` 使用已发现的写能力、声明字段及准确版本。审批显示已选系统、登记名称、动作、提交员工、版本及每一行名称／值。重复名称、无效或超限字段在审批前拒绝；服务端执行当前声明必填项、角色及可选捕获检查。同一原生调用保留重试 UUID。[写入协调器](../office/README.zh.md#external-write-evidence)先持久派发再调用客户适配器，并阻止新的调用 UUID 重放相同未决业务输入。结构化输出区分成功、明确拒绝及未知；仅权威持久成功包含已确认结果字段。其他 Agent 或之后未关联的轮次不会获得该写入贡献。

旧子会话在模型或工具准入前使用保留的父证据恢复归属，插件重载后同样适用。对已证实归属的子会话，继续前先追加既有的必读继承事件；待处理新输入不能绕过目录检查。完整父链没有任何办公声明时，即使无目录，也可证明原生归属。父会话缺失、无查询服务，或具有办公归属的父会话缺少准确目录时，以 `OFFICE_NATIVE_AUTHORITY_UNAVAILABLE` 拒绝继续并提示从备份恢复。新建且归 runtime 拥有的子运行，先完成父归属恢复再继承；已证实的新原生子运行在当前进程保留原生状态。取消及插件卸载会中止父观察，并等待在途读取结束。见[旧子会话升级指南](../../../docs/upgrade-guide/v0.2.1-alpha.2/office-legacy-child-history/guide.zh.md)。未确认的历史不会变成当前员工分配或权限授予。

### 会议纪要自动化

存在原生技能注册表时，这个可选插件还提供内置 `office-minutes` 技能。可在工具页面选择其已安装入口，或发送 `/office-minutes` 并附上会议材料和输出要求。已有会议纪要请求模板仍是独立的待发送起点。项目和用户技能的优先级保持不变，卸载本插件会移除其内置贡献。

技能读取所提供的记录，通过原生 `workflow` 工具依次调用提取和复核子 Agent，再写入、核验并交付真实 Markdown 文件。请求 Word 文件时还需要已安装的 `office-docx` 技能。技能保留不确定事实，不推断缺失的负责人、日期或决定。缺少材料或无法执行工作流时，会先报告问题，不声称已完成。[技能指令](assets/office-minutes/SKILL.md)定义工作流脚本和交付步骤。

原生工具调用、工作流成员和终态结果保留在会话历史中，包括失败或取消的尝试。只有实际写入文件且原生 `present` 操作成功后才会出现交付记录。停止不会删除已经写入的文件。原生策略继续约束读取、工作流子 Agent 和写入，加载技能不授予权限。没有独立的明确请求时，此技能不发送纪要，不创建办公任务、提醒或公司系统提交。

### 日报和报销检查

同一提供方还贡献 `office-daily-report` 和 `office-expense-check`。可在工具页面选择其已安装入口，或显式调用并提供来源路径和要求。[日报](assets/office-daily-report/SKILL.md)要求明确的日历日期和实际工作记录或已授权办公读取结果。提取与复核工作流区分已完成工作和计划，并标明未知数据和覆盖范围。

[报销检查](assets/office-expense-check/SKILL.md)读取真实 JSON 台账和明确的 JSON 公司规则文件。原生工作流解析文件，以整数最小货币单位分别计算各币种合计，识别重复票据、缺失的规则必填项、无效金额、单项超限和申报合计不符，再由子 Agent 复核真实证据和检查结果。规则文件声明币种精度、单项限额和必填字段；缺失规则会停止执行或明确保留为未检查。从其他格式提取数据需要已安装读取工具，并保留来源引用。不推断汇率、税务规则、舍入、审批结论或付款。

这两个报告技能通过已有原生工具写入、重新读取并交付真实文件。报销报告在复核文本旁保留准确的结构化检查。原始输入留在原处，失败或取消尝试保留在原生历史中，不出现已完成交付。这些技能不提交业务操作，也不发送报告。

### 原生任务提醒

`office-task-reminder` 使用已有的 `schedule_create`、`schedule_list`、`schedule_update` 和 `schedule_delete` 工具。[技能指令](assets/office-task-reminder/SKILL.md)要求提醒内容、明确时间及以当前 AI 会话作为目标。本地日历时间需要日期和 IANA 时区。不会把同事、外部聊天或办公事项静默替换成当前会话；创建办公工作仍需通过已有的关联和审批流程单独明确请求。

技能报告真实保存的任务标识和目标，并通过原生列表核验活动状态。取消会删除选中的原生提醒并保留原工具调用及结果历史，无法撤回已经入队的输入。停止模型轮次不会删除已保存提醒。真实到期投递回执确认持久收件箱输入，模型回复和任务完成仍是独立事实。已配置 Host 必须运行才能投递，并沿用已有循环规则和崩溃恢复语义。不安装额外调度器，也不授予权限。

<a id="model-experience"></a>
## 模型体验

### 内部工作创建

#### 模型看到什么

选定提醒的会话收到 [office_create_work schema](../../../docs/tool-catalog.zh.md#office_create_work)。该工具创建内部任务／待办并返回结构化事项坐标，不向外部公司系统发消息，也不安排 Agent 提示词。未提交有效提醒的会话不会获得工作创建 schema。

#### Token 影响

提供的 schema 及返回 JSON 消耗请求 token，不额外安装系统提示词区段。

#### KV Cache 影响

作用域工具的增加及移除沿用原生工具更新机制，不改写已有历史或系统提示词。

### 公司系统查询

#### 模型看到什么

提交的已配置系统提供 [office_list_actions](../../../docs/tool-catalog.zh.md#office_list_actions) 和 [office_read_action](../../../docs/tool-catalog.zh.md#office_read_action)。模型先发现当前目录，再查询明确声明的读取动作。读取状态区分真实数据与网络／认证失败。业务字段属于数据而非指令，写动作声明不能通过读取工具执行。

#### Token 影响

作用域 schema、目录元数据及真实查询字段消耗请求 token，原生结果处理负责输出预算和呈现。

#### KV Cache 影响

工具沿用原生工具更新机制。查询结果追加到已有会话，不改写先前消息或系统提示词。

### 公司系统提交

#### 模型看到什么

选中系统的作用域提供 [office_write_action](../../../docs/tool-catalog.zh.md#office_write_action)。发现返回 `write_supported` 以及声明字段名称、标签、必填标记和长度上限。模型提供名称唯一的文本行及审核版本。持久输出包含执行标识、原重试 UUID、阶段、状态及脱敏结果。未知结果指示模型核查该执行，而非再次提交业务操作。

#### Token 影响

作用域 schema、公共字段元数据、提交值及真实回执消耗请求 token。审批使用同一不可变调用字段，不增加系统提示词章节。

#### KV Cache 影响

原生工具机制更新作用域可用性。调用和回执追加到现有历史，不改写先前消息或 Session 格式。

### 已提交的公司文件

#### 模型看到什么

员工 Host 在接纳前记录文件版本的描述快照。`office_read_file` 读取已校验的 UTF-8 窗口，`office_read_pdf` 提取真实 PDF 的指定一页，`office_read_docx` 提取 Word 正文段落／表格单元格，`office_read_xlsx` 返回准确保存的电子表格单元格。可选的 `office_read_pptx` 读取明确指定的已保存幻灯片或备注部分。其 schema 和实际结果沿用原生工具流程。文件文本和公式是不可信的任务数据。捕获不会授予准确运行 Agent 和办公授权之外的访问权。

#### Token 影响

提交元数据、作用域 schema 和返回文本消耗请求 token。文本读取器限制字符数，XLSX 限制完整已存单元格数。PDF、DOCX、XLSX 和 PPTX 还限制转义后完整原生工具内容 JSON 的字节数。原生结果预算仍然生效。

#### KV Cache 影响

新上下文和工具结果追加到日志历史，已有消息保留，作用域工具可用性遵循原生机制。

### 会议纪要

#### 模型看到什么

原生发现发布 `office-minutes` 的说明。显式调用或已有 `skill` 工具通过原来的已记录技能机制加载完整指令。指令要求使用已有工作流、文件系统和交付工具；本包不提供替代执行器或模型响应。工作流子请求携带原始材料和待复核草稿。

#### Token 影响

技能目录、已加载指令、两个子请求、工具结果和复核文本消耗原生请求令牌。原始材料会发送给每个子 Agent，已有工具和模型预算继续适用。

#### KV Cache 影响

技能指令和执行结果通过已有原生历史追加。提供方不改写此前消息，也不额外安装系统提示区段。

### 日报、报销检查和提醒

#### 模型看到什么

已有目录发布这三个新增技能的说明。原生加载记录其指令。报告技能调用已有工作流和文件系统工具；报销工作流返回准确的结构化检查及来源复核。提醒指令调用已有 Schedule 工具，并检查实际成功或结构化校验错误。此提供方不会仅因加载指令就创建执行或投递记录。

#### Token 影响

已加载指令和原生结果消耗正常请求令牌。日报提取和复核各自接收来源文本。报销复核接收解析后的台账、规则和计算检查。提醒执行增加其实际 Schedule 调用和到期提示，原请求预算仍具有约束力。

#### KV Cache 影响

新增目录元数据和显式加载的指令沿用已有技能机制。执行和到期输入通过原生历史追加，不改写此前消息，也不改变 Session 格式。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待办

- 报告技能需要已配置的原生工作流引擎和文件工具。它们提供指令，来源解释和复核质量仍由所选模型及已安装读取工具决定。报销计算接收有来源的 JSON 和非负十进制金额，必须明确声明零到六位的币种精度；换汇、退款和税务计算需要单独明确处理。未知规则保留为未检查。
- 提醒投递支持当前原生会话，并需要已有 Host Schedule 服务。外部通知和创建办公工作属于独立操作。已保存投递回执仅证明收件箱投递，不证明模型回复或任务已完成。

- 真实客户适配器及任意带参数查询仍属独立工作。员工历史提供明确结果核查，本插件不新增独立的原生核查工具。仅有元数据不安装读或写实现。员工表单独立于原生工具审批，使用同一协调器。
- 取消可能发生在内部业务提交之后。稳定请求标识可恢复确认，取消不会回滚已提交事项。
- 员工 Host 仍是受信任环境，本插件不构成面向其管理员或独立配置的原生工具的安全边界。
- 已提交 PDF 提取可选文本，DOCX 提取正文段落／表格单元格，XLSX 读取准确保存的单元格并明确标注陈旧或缺失的公式缓存，可选 PPTX 读取已保存幻灯片或显式备注文字。公式重算、其他 Office 格式、OCR 及视觉版面仍属于独立工作。
