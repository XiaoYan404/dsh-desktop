# @deepseek-ai/dsh-client-ui-office

English | [中文](README.zh.md)

## Summary

This optional plugin adds an employee navigation rail, a workbench dashboard, calendar lists, work filters, a company directory and profile editing. Employees use a configured local identity or sign in to a [central office service](../../enterprise/office-gateway/README.md). Native Conversations, settings, workspace navigation and plugin management retain their existing owners.

Web and Desktop share the office styles. Available panel width controls dashboard stacking, metric columns and directory layout. Narrow Drive views place the folder tree above the file table and scroll the command bar horizontally; the table retains its own horizontal scrolling. Office controls inherit the selected font and retain keyboard focus, system contrast mode and touch targets. Desktop caption spacing follows the shell's platform and fullscreen markers.

See the [Drive-reader reference](../../enterprise/office/drive-readers/README.md) for optional image, authorized knowledge and Office delivery-check configuration, authority, retention and limitations.

## Use this package

In Identity and audit, filter the combined metadata by source, actor, target, exact action and time range, then choose Apply filters. Sources include the original audit categories and execution stages, invitations, central policy, groups and actual usage. Filter times use the device’s local timezone; record times show the displayed timezone. Read older records extends the current search. Editing a filter disables export until the new search succeeds. An invalid filter stays visible and sends no request.

Export displayed records reauthorizes every displayed row in batches of at most 100 and compares all metadata fields before creating one NDJSON file. Changed records require a fresh search; a failed batch produces no partial download and preserves reviewed rows for an explicit retry. Closing or losing administrator access before dispatch prevents the download. Success feedback follows the existing browser file saver. Office administrators can query metadata while chat is disabled; message history still requires its original chat authorization. An older Host without the collaboration RPC remains unavailable.

Open Notifications → Collaboration and notifications for the unified recipient inbox, groups, notification preferences and finite repeat meetings. The panel needs the office service’s collaboration methods; an older Host shows an unavailable-service notice with Refresh instead of confirming unsupported operations. The existing calendar, private chat, files and login keep their original owners.

Group owners explicitly confirm closure or ownership transfer to a current member. Selected attachments can be removed before sending. Switching panel tabs retains form inputs. An unconfirmed message or meeting retries its unchanged request identity; definitively invalid message input can be corrected. Account changes and authorization denials discard private forms and prevent late replies from restoring them. Confirmed operation feedback remains visible after the dialog closes.

Administrators can review all role scopes, preserve administrator office access and save a confirmed central policy. Concurrent policy changes preserve the draft and require Load latest policy. Member access shows blocked cleanup, completed revocation and restoration separately: Continue cleanup reuses the initiating administrator’s request; restoration requires an active member and explicit remaining restrictions, and never revives old sessions or invitation codes. Audit-query failure does not disable policy administration. Usage shows actual reported counters and record coverage; missing counters and costs stay unknown.

When the configured central gateway advertises onboarding invitations, administrators can open an active member's password management and choose **Onboarding invitations**. Review the member, role and explicit expiry in this device's timezone, then issue a code. The code appears only in that dialog and copies only on request; closing it discards the code. An uncertain issue retries its unchanged request. A confirmed retry returns metadata without recovering the code, so revoke and issue another code when delivery was lost. Revoking a code does not undo a password already set.

The signed-out login form offers **Accept onboarding invitation** only for a gateway advertising this capability. The recipient enters the code and matching first password, then signs in through the existing login form with the returned member id. Activation creates no authenticated session. Failed activation retains the form; an uncertain result asks the recipient to try ordinary login with the chosen password. Codes and passwords remain in transient component state and form controls, outside shared snapshots. Account, role, target-authority and capability changes close the dialog and withdraw pending publication. Local identity mode and older gateways keep the existing login interface. The [office service](../../enterprise/office/README.md) owns invitation configuration, eligibility, persistence and recovery.

Office history access also governs workspace metadata: another employee cannot archive, stop, restore, pin, unpin or reorder an attributed Conversation, including using it as an order anchor. Command results, follow baselines and queued increments omit its Session id. Session-scoped file lookups, reads and watch frames recheck the same visibility before access and delivery; replacing the employee during a read withholds its bytes and metadata. Checks do not activate cold Agents or modify Session records. Workspace directories remain Host resources; this filtering does not create enterprise filesystem tenancy.

Native file, terminal, job and Changes access also requires the employee's current role to match the role claimed in the Session. A retained request keeps its original employee and role restriction even after a newly reviewed input claims another role. Fresh requests use the new claimed role; ordinary employee history remains browsable. Every resource check still reads current authenticated authority and original Session affiliation. Request snapshots only restrict access and grant no authority; unassociated Native Sessions retain their existing access model.

Enter a system or skill name, contact person and requirements, then save. **My customization requests** reopens your own saved versions for editing. **Export saved version** downloads JSON after checking the reviewed version is still current. Unsaved changes and unconfirmed saves cannot be exported; retry an unconfirmed save without changing its input, or explicitly load a newer conflicting version. Closing a form withdraws its UI but does not cancel a server save already admitted. These requests are **saved, not sent**; deliver the export through a company-approved channel. ### Files in employee chat

Each contact keeps its own selection when switching contacts, opening a task/event/to-do form or closing the chat. Remove files before sending, or send files with an empty caption. Downloads verify message/file coordinates, metadata, size and SHA-256 before browser saving. Hook snapshots contain only JSON metadata and status. If file policy cannot be read, the composer keeps text chat available and offers Retry.

## Understand the implementation

After a bundle has been removed and its plugins stopped, reinstalling a changed package version loads that version's code at the same paths. Overwriting an installed package, relinking a package, or replacing code without changing its version retains the existing restart requirement. ### Home prompt handoff

#### What the model sees

Only an explicitly submitted request reaches the model. The `submit` option follows the existing queue submission path and durable Session history. #### KV Cache effect

## Known Limitations and Deferred Work

- The integration catalog supports registration, connection checks, private Conversation associations, declared business queries and reviewed employee write forms. Outcome checking requires an installed customer adapter implementation. Reviewed associations enter native model context; optional office tools create internal tasks/to-dos and read or submit declared operations in selected company systems with native approval. Tools prepares native skills and task requests; availability does not guarantee a configured model or dependency. Drive references support UTF-8 text up to 1 MiB, bounded selectable PDF text, DOCX body paragraphs/table cells, saved XLSX cells and explicitly selected PPTX slide/notes text; formula recalculation, other Office formats and OCR remain pending.
- Private messages, sent files and per-contact text/file drafts survive a browser reload after confirmation on a durable-capable server. Text saves are debounced by 350 ms; unconfirmed text or file edits can be lost when the window closes. Failed saves retain local input for retry. Concurrent changes require an explicit choice to load the saved draft or keep this window's input. Group chats remain pending.
- Invitation replies, status cancellation, meeting content and member editing, visible-calendar overlap advice and opt-in internal member availability are available. External calendar availability/delivery, recurring and cross-day meetings remain pending.
- Unsent home File handles remain private to the current browser window and are lost when it closes or reloads. Adopted attachments and later send failures follow native Conversation ownership. Item links are browser-local navigation state, not cross-device identity or an authorization boundary. Native text drafts/history restore on reload; unsent native attachment handles require reselection after the window closes.
- Central password sign-in is available through the separate office gateway. SSO, directory synchronization and multifactor authentication remain pending. The employee's local Host is trusted; neither a fixed principal nor central office sign-in creates an authentication boundary against that Host's administrator or native Agent tools.

### Dev Note

Account/contact dictionaries read only their own stored entries. Directory ids such as `constructor`, `__proto__` and `toString` remain valid; absent drafts, errors and grants do not inherit JavaScript prototype values. Real storage/restart and browser acceptance cover messaging, draft restoration and shared account conditions for these identities.

Client source lives in [src/client](src/client); the Host Remote adapter is [src/index.ts](src/index.ts). Keep Agent execution in the native Conversation pipeline and business authorization in the office service.

The current Remote carrier checks argument positions exactly. Latest chat reads pass both the peer and an explicit `undefined` cursor.
