# 恢复旧办公子会话时保留父目录记录

[English](guide.md) | 中文

## 变更

旧子 Agent 会话可能没有 `office/run-inherited` 记录。保留的父会话中若恰有一条本地目录记录，且子标识及创建时间准确匹配，员工 Host 会从该记录之前的事件推导原办公归属。父会话后来的角色审核不能授权该子会话。读取时应用限制，不激活 Agent、不写日志；执行恢复会在继续前追加既有的继承事件，当前员工及角色核验仍然必需。

准确目录证明原创建范围，或完整保留的父链在所有时点均无办公声明时，原生子会话继续保持原生行为。父会话缺失，或具有办公归属的父会话缺少匹配目录时，无法重建归属。员工 Host 隐藏这些未确认的子会话，直接投影读取返回不存在；办公运行守卫在模型／工具执行前拒绝继续，并要求恢复原父会话／目录备份。当前登录不能认领缺失的历史。不改写 Session 格式或原始记录。

Host 会按缓存状态版本 3 重建旧归属检查点。子会话必读继承记录与首次待处理角色分别有标记，因此尚未认领的排队审核不能替换原创建角色。同一员工在子会话明确认领的角色审核继续有效，员工矛盾则继续受限。

## 迁移

1. 将父子 Session 目录一起备份，保留每个已提交代次及父目录记录。
2. 同时升级员工 Host 及办公工具插件。既有 Session 查询服务提供异步父记录读取。
3. 用原员工及角色恢复已归属的旧子会话，核对其他员工或变化后的角色不能读取私有历史、驱动模型或工具，并确认未关联办公的原生子会话仍能运行。
4. 旧子会话消失或提示无法核验归属时，从原备份恢复缺失的父会话／目录数据，不依据当前登录分配归属。证据恢复后，确认原员工能读取并继续该子会话。回退时保留原始 Session 记录，它们仍使用既有格式。
