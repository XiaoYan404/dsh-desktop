# 修改事项优先级前升级办公读取器

[English](guide.md) | 中文

## 变更

任务和待办可保存可选优先级，没有该值的既有事项仍按普通处理。优先级变化会在 `enterprise_office` 保存 `work_prioritized` 通知和审计记录，旧读取器会明确拒绝此判别值。当前读取器可接受既有记录，领域版本 1 和原生 Session 格式保持不变。

## 迁移

1. 停止共享办公后端的员工 Host 和集中网关。备份对应后端，使用 JSON 时包含 `storage-json.root`。
2. 选择事项优先级前，同时升级员工 Host 和集中网关。保留既有存储配置和数据目录。
3. 打开已有任务或待办，修改优先级后确认标识、截止信息、负责人、状态和操作历史保留，并检查其他参与者的通知。既有 `updateWork` 调用不提供优先级时保留原值；明确选择普通会清除已保存的非普通值。
4. 降级时仅恢复匹配的升级前办公存储备份。保留原生 Session 目录；之后的办公修改不包含在该备份中。
